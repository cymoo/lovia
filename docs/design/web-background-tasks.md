# 后台任务：子任务和后台命令放进一个面板

> 状态：已实现（#540–#542、#544、#545，v0.9.281–0.9.285）· 2026-11-26 · 范围：`lovia/workspace`（`local.py`、`types.py`、`protocol.py`、`tools.py`、`remote/`）、`lovia/plugins/subagents.py`（一个字段）、`lovia/web`（`workspaces.py`、`api/workspace.py`、`api/sessions.py`、`subagents.py`、`store.py`、`static/js/files.js`、`sessions.js`、`chat.js`、`i18n.js`、`static/styles.css`、`templates/index.html`，新增一个监视模块和一个面板模块）。不加依赖。
>
> 行号指向 `main`（`89be7230`，v0.9.280）。

## 背景

一个对话背后可以有两种东西在跑：子任务（`Subagents` 插件派出的子 agent）和后台命令（`shell(background=true)` 启动的进程）。现在它们在界面上互不相干，而且后台命令几乎不可见：

| 问题 | 位置 |
| --- | --- |
| 两个入口：子任务在顶栏「任务 N」弹层，后台命令在文件面板「变更」页顶部，面板不开就看不到 | `sessions.js:582`、`files.js:446` |
| 界面看不到命令的输出：缓冲只有 30k 字符，模型一读就清空，界面无法旁观 | `local.py:409`、`local.py:479` |
| 用户在面板点停止，会替模型取走末尾输出并把退出标成已读，模型下一轮既收不到退出提醒也读不到输出。注释写的是相反的行为 | `local.py:1623`、`tools.py:713`、`api/workspace.py:571` |
| `ProcessStatus` 没有起止时间，行上显示不了耗时 | `types.py:129` |
| 点子任务会整页跳到子对话 | `sessions.js:728` |
| 命令列表靠 8 秒轮询，只在文件面板打开时刷新；已结束的行一直留着 | `files.js:500` |
| 服务重启、对话换目录、远程连接断开后，命令的记录全部消失 | `workspaces.py:573` |
| 没有 workspace 的 agent 打不开右侧面板（它也可以有子任务） | `files.js:219` |

## 结论

1. **界面合并，内核不合并**。右侧面板加第三个页签「后台」，子任务和后台命令在同一个列表里。数据模型和工具保持两套：子任务是持久化的对话，后台命令是工作区会话里的临时进程。合并发生在前端。
2. **运行中的输出留在内存**：每个进程一个环形缓冲，按字符偏移量读取。模型和界面各读各的，互不影响。
3. **结束后的输出存成本地文件**：每条记录一个文件，放在数据库旁边的 `process-logs/` 里，随对话删除，按总量清扫。不进 SQLite。
4. **内存只和正在运行的命令数成正比**：命令结束 60 秒后，缓冲缩到模型还没读的那一段。
5. **列表靠服务端推送刷新**，不轮询。只有打开着的日志详情轮询，而且会自己降频。
6. **分五个 PR**，第一个是修现有的停止 bug，可以先单独合。

## 用词

整体叫「后台任务」，页签叫「后台」。两类分别叫「子任务」和「命令」。界面上不再出现「任务」和「后台进程」两套说法。

### 入口

- **顶栏按钮**保留，只在对话有后台任务时出现。它是状态指示加开关：点击打开面板并切到「后台」页；已经在「后台」页时再点关闭面板。不再有弹层。
- 进入子对话后，这个位置仍然是「← 返回父对话」（`sessions.js:660`），不变。
- **面板的开关从文件面板里拆出来**。现在 `setOpen` 用 `open && state.available`，`available` 来自 `agent.workspace`（`files.js:219`）。改为面板自己控制可见性，只有「变更」「浏览」两页依赖 workspace；没有 workspace 的对话只显示「后台」页。
- 「变更」页顶部的进程条删除。

### 顶栏按钮的状态

按优先级取第一个成立的：

| 状态 | 显示 |
| --- | --- |
| 有子任务等待审批或回答 | 琥珀色。按 `pending_approval` 或 `waits_on.kind` 判定，不是「不在运行就算待审批」（现在的 `taskState` 是后者，`sessions.js:589`） |
| 有用户没看过的失败 | 红点。打开「后台」页即清除，做法和文件按钮的未读角标一样 |
| 有子任务在跑 | 「N 运行中」，圆点带动画 |
| 只有命令在跑 | 「N 运行中」，圆点静止。dev server 一跑几小时，持续的动画是噪音 |
| 都已结束 | 「后台 N」 |

### 列表

- 分「运行中」和「已结束」两组，待审批的排最前，组内按开始时间倒序。「已结束」默认折叠，只显示数量。
- 每行：类型图标、标题、计时或结果、悬停时出现停止按钮。命令的标题是等宽单行命令，子任务的标题是 `tN` 加任务名。失败的行标红，带退出码。
- **第二行**只给运行中的行：命令显示最后一行输出，子任务显示当前步骤。它跟随列表的刷新节奏（收到推送或打开面板时），不每秒更新。已结束的行第二行是结果和耗时。
- 计时沿用现有的共享定时器（`sessions.js:614`）。
- **停止**：命令直接停，不确认。子任务第一次点击变成「确认停止」，几秒后复原，因为停掉它会丢掉全部进展。

### 命令详情

点命令行，在面板内下钻。**复用文件查看器**的位置和外壳：面板默认只有 340 到 440 像素宽（`styles.css:5180`），日志在这个宽度里难读，而查看器已经有换行开关、宽屏并排和放大弹窗。

- 头部：完整命令和复制按钮、目录、起止时间、退出码或结束方式。
- 正文：日志。运行中时跟随末尾；用户往上滚就停止跟随，出现「跳到最新」。
- 操作：停止、复制、下载。下载的是服务端保留的内容，不是页面上渲染的那几千行。
- 头部被丢弃时，日志开头标「…已省略前面 N 个字符」。

### 子任务详情

第 5 步才做。在那之前，点子任务行仍然打开完整子对话，行尾的 ↗ 图标说明这一点。

- 任务说明（折叠）、当前步骤、统计（N 个工具调用、M 个失败）、最终报告、「打开完整对话」。
- 不在面板里再嵌一份 transcript：`chat.js` 的渲染是单例，嵌进去代价太大。
- 当前步骤现在取自已渲染的聊天 DOM（`activity.js:86`），面板里拿不到，需要服务端给一份轻量摘要。

### 对话内

- `shell(background=true)` 的工具卡加「查看输出」，打开对应的命令详情。
- `spawn_subagent` 的工具卡加「查看」，打开对应的子任务详情（第 5 步）。
- 子任务的审批托盘留在输入框上方，不动。

## 输出的三个阶段

| 阶段 | 位置 | 保留多少 |
| --- | --- | --- |
| 运行中 | 内存，在执行命令的那台机器上 | 最新 1M 字符 |
| 输出流关闭后 60 秒内 | 同上 | 同上，等 web 层取走 |
| 之后 | web 层的本地文件；内存里只留模型没读的部分 | 文件里是取走时的整个缓冲 |

### 环形缓冲和读取契约（core）

`_TailBuffer` 换成按绝对偏移量寻址的环形缓冲。偏移量按**字符**计，从进程启动算起：现有缓冲存的就是解码后的 `str`（`local.py:1699`），模型侧的上限也是字符数，按字符计就没有多字节字符跨页、跨淘汰边界的问题。

- 上限是 `WorkspaceLimits` 的新字段，默认 1M 字符。超出时丢最旧的。
- 合并过小的块，逐行打印的进程不应该留下上万个小字符串。
- **模型的读取**（`read_process_output`）：从模型的游标读到末尾，最多取最新的 `max_shell_output_chars`（默认 30k），更早的丢弃并报 `truncated`。语义和提示词不变。
- **界面的读取**是新的只读调用：

```python
async def peek_process_output(
    self, process_id: str, *, after: int = 0, limit: int
) -> ProcessChunk: ...

@dataclass(frozen=True, kw_only=True)
class ProcessChunk:
    process_id: str
    text: str
    base: int   # 缓冲里最早还在的偏移量；大于 after 说明中间丢了一段
    next: int   # 下次从这里读
    eof: bool   # 输出流已关闭，并且已经读到末尾
```

  它不移动模型的游标，也不改 `exit_seen`。`eof` 以读取任务排空为准，不以进程退出为准：进程可以先退出，管道稍后才排空（`local.py:1614`）；后代进程还占着管道时，`eof` 一直为假。

- `ProcessStatus` 加 `cwd`、`started_at`、`ended_at`、`output_chars`、`last_line`。

### 停止和「模型已读」分开（core）

- `kill_process` 是给模型用的工具：停止并返回末尾输出，算模型读过。不变。
- 新增 `stop_process(process_id) -> ProcessStatus`：只停止，不取输出，不动 `exit_seen`。web 的停止路由改用它。
- 两者共用同一段终止进程组的代码。

### 结束后缩减（core）

读取任务结束（输出流关闭）60 秒后，缓冲缩到模型游标之后、最多 `max_shell_output_chars` 的那一段。会话关闭时取消这个定时。

- 只按模型的游标回收，不看 `exit_seen`。模型可以在进程退出、管道还没排空时就读到退出（`read_process_output` 只等一秒，`local.py:1614`），之后后代进程写出的内容仍然在游标之后，要留着。模型全部读完的，游标在末尾，自然只剩状态。
- 输出流没关闭就不缩减：后代进程占着管道时，缓冲保持 1M 的上限。

- 这条规则在引擎里，不依赖 web 层来通知，所以直接用库的人也有上界。
- 60 秒对 web 层足够：监视任务两秒内就会取走。
- 墓碑保留到会话关闭（现状）。一条没读过的墓碑最多 30k 字符。

### 结束记录（web）

每条记录一个文件：

```
<数据目录>/
  lovia.db
  attachments/<对话>/…
  process-logs/<对话 id>/<进程 id>.log
```

- 位置规则和附件目录一样（`store.py:719`）：数据库旁边；内存数据库模式下用临时目录，进程退出即清除。
- **格式**：第一行是一行 JSON，之后是输出正文，原样保存。先写临时文件再改名。

```json
{"id": "bg-3f9a1c", "command": "pytest -q", "cwd": "/repo", "started_at": 1764120000.0, "ended_at": 1764120042.5, "status": "exited", "exit_code": 1, "ended_by": "exit", "base": 0, "chars": 48213}
```

  `ended_by` 是 `exit`、`user`（面板停止）、`model`（`kill_process`）、`shutdown`（服务退出）、`closed`（会话被关闭，比如换目录）、`lost`（远程连接断开）之一。`base` 是正文第一个字符的偏移量，界面读文件和读内存用的是同一套偏移量。命令过长时截断，JSON 行不含原始换行。

- **不选 SQLite**：命令日志是可以随时扔的缓存，对话数据库存的是不能丢的东西。放进同一个文件，数据库只涨不缩、备份被拖累、用户没法单独清理，还要加表和迁移。
- `process-logs/` 可以随时手动删除，应用只会显示没有历史记录。这是约定，写进文档。

### 谁来写记录（web）

所有让进程消失的路径共用一个收尾函数：取尾部、写文件、发事件。

- **监视任务**：服务里一个任务，每两秒看一遍有活进程或输出流没关闭的会话。进程退出时发事件；**输出流关闭后才写文件**，用 `peek_process_output` 分页取到 `eof`。进程已退出而后代还占着管道时，不写文件，界面继续读内存，后来写出的内容不会丢。这样的进程到会话关闭时才归档。会话在 `shell` 工具调用完成时被标记为需要查看；其余会话不查，远程工作区因此不会被空查。
- **关闭路径**：服务退出（`deps.py:296`）、会话因换目录被关闭（`workspaces.py:573`）。顺序是**先停进程，再取输出，再写文件，最后关闭会话**：还在跑的 dev server 不停就永远等不到 `eof`。停止之后进程组被杀，管道随之关闭。每个会话的收尾有两秒超时；超时也把已经取到的正文写下来，只有一个字符都没取到时才只存元数据。收尾放在 `WorkspaceSessions` 里，新增的关闭路径不用各自记得。
- **删除对话**（单个或全部，`api/sessions.py:304`、`api/sessions.py:577`）不收尾，直接和附件目录一起删。
- 服务被强杀时来不及写，正在跑的那几条会丢。不为此定期落盘。

### 清理

| 规则 | 值 | 何时执行 |
| --- | --- | --- |
| 每个对话保留的记录数 | 30 | 写入新记录时，删这个目录里最旧的 |
| 所有记录的磁盘总量 | 300 MB（可配置） | 并进现有的每小时清扫（`deps.py:310`）和启动时的清扫，按修改时间从旧到新删 |
| 无主目录 | | 同一次清扫，做法和附件目录一样（`store.py:759`） |

总量不在每次写入时检查，可能短暂超出，对缓存来说无所谓。

## 接口和事件（web）

| 接口 | 说明 |
| --- | --- |
| `GET /api/sessions/{id}/processes` | 活着的进程加上这个对话的结束记录，合成一个列表。同一个进程两边都有时取结束记录 |
| `GET /api/sessions/{id}/processes/{pid}/output?after=&limit=` | 返回 `{text, base, next, eof}`。进程还在引擎里且没有记录文件时读内存，否则读文件 |
| `GET /api/sessions/{id}/processes/{pid}/log` | 下载：有文件返回文件正文，没有则返回缓冲里的全部 |
| `POST /api/sessions/{id}/processes/{pid}/kill` | 改用 `stop_process` |

- `/api/events` 加一个事件 `processes_changed {session_id, running}`：进程启动、结束、被停止时发。顶栏计数、面板列表、侧边栏指示都只听这一个信号，多个标签页之间一致。
- 事件流不重放断线期间的事件（`api/events.py:15`）。重连时除了现有的会话和 run 快照，还要重新取当前对话的进程列表：断线期间一个进程退出、另一个启动，计数不变，列表却变了。
- `/api/sessions` 的每一行加 `processes_running`，来自监视任务的状态。不能从 `/api/runs` 取：它只列活跃或挂起的 run（`api/sessions.py:200`），对话空闲而 dev server 还在跑的情况正好漏掉。

## 性能

**服务端**

- 追加是按块的，不逐行处理。`last_line` 在被问到状态时从缓冲尾部现算。
- 写记录文件走线程，不阻塞事件循环。

**传输**

- 只有打开着的日志详情轮询。有新输出时间隔 1 秒；连续为空时退到 5 秒，一有数据回到 1 秒；页面不可见时停止；读到 `eof` 后停止。
- 每页最多 256K 字符。客户端落后超过缓冲时，`base` 会大于它请求的偏移量，界面插一行省略标记后从 `base` 继续。
- 用轮询不用 SSE：拉取天然有背压，远程工作区也不用多一条长连接。

**前端**

- 每批输出一个块元素，配 `content-visibility: auto`，屏幕外的块不参与布局。不用单个 `<pre>`：开着自动换行时，每次追加都要重排整段。
- DOM 里最多留约 5000 行，从头部整块移除。单行超过 2000 字符截断显示。
- 去掉 ANSI 转义。`\r` 刷新的进度条只显示最后一段；一段 `\r` 可能跨两页，折叠要带状态。
- 不做语法高亮。

**已知的不足**：`tqdm`、`npm install` 这类 `\r` 刷新的输出会占掉缓冲，把更早的日志挤出去。界面上看是折叠后的，但缓冲和记录文件里存的是原样。在引擎里折叠会改变模型读到的内容，等实际遇到再说。

## 远程工作区

和本地没有区别：记录文件存在 lovia web 这台机器上，远端不留文件；web 层通过同样的接口读状态和输出，每次调用是一次 RPC。三处行为不同：

1. **连接断开时拿不到输出**。远端引擎随连接结束，记录只有元数据，`ended_by` 是 `lost`。
2. **收尾的两秒超时**对远程更容易触发，结果同上。
3. **起止时间是远端的时钟**。耗时用同一台机器的两个时间相减，不受影响；「几分钟前」用 web 层观察到的时刻。

`peek_process_output` 和 `stop_process` 加进远端引擎的调用表（`remote/serve.py:47`）。引擎仍然只用标准库。

## 子任务和工具卡的关联

`spawn_subagent` 返回的 `t1` 只在一次 run 内唯一（`plugins/subagents.py:105`），子会话 id 是 web 另外生成的（`web/subagents.py:267`）。同一个对话的两次 run 都可以有 `t1`，按标题匹配会打开错的任务。

- `ChildSpec` 加 `spawn_id`：插件为每次派出生成的唯一 id，同时随这次工具调用的结果存进 transcript。
- web 在子会话的行上记下 `spawn_id`，工具卡用自己结果里的 `spawn_id` 找到子会话。
- 不用工具调用的 id 作键：有的供应商每一轮都从同一个 id 开始，同一个 run 的两轮各派出一个子任务就会撞上，加上父 run 的 id 也分不开。
- `spawn_id` 放在结果的结构化字段还是文本里，第 5 步定。验收要从刷新后的历史卡片点进去，并覆盖同一个 run 内调用 id 重复的情况。

## 默认值

| 项 | 值 | 可配置 |
| --- | --- | --- |
| 运行中的缓冲 | 1M 字符 | 是，`WorkspaceLimits` |
| 模型一次读取 | `max_shell_output_chars`，默认 30k | 已有 |
| 结束后缩减的延迟 | 60 秒 | 否 |
| 每个对话的记录数 | 30 | 否 |
| 记录的磁盘总量 | 300 MB | 是，web 配置 |
| 页面上的日志行数 | 5000 | 否 |

内存最坏情况：正在运行和刚结束一分钟内的命令各 1M 字符，加上每条没读过的墓碑 30k。每个运行中的命令背后是一个真实的系统进程，本身的开销远大于缓冲。

## 不做和暂缓

- **统一的 Task 抽象**：两者的生命周期和存储都不同，硬合只会让两边都变复杂。
- **完整终端模拟**：xterm.js 是重依赖。后台命令没有 stdin，也不是 TTY。
- **把定时运行并进来**：它们不是这个对话的子项，有自己的视图。
- **运行中就落盘**：只为强杀时不丢几条记录，不值得。
- **引擎里折叠 `\r`**：会改变模型读到的内容。
- **「清除已结束」按钮**：清理全部自动，列表靠折叠控制长度。
- **按天数淘汰**：按总量从旧到新删，效果相同，少一个设置。
- **面板里嵌完整的子对话**：见「子任务详情」。
- **空闲工作区会话的回收**：现有行为，和这次无关，另开 issue。

## 合并顺序

每一步合入后都有完整可用的入口。

1. **修停止 bug（core + web）**：加 `stop_process`，web 的停止路由改用它。验收：用户在面板停止 → 模型下一轮收到退出提醒 → 模型第一次读取拿到末尾输出和退出码。不依赖后面的步骤。
2. **缓冲和读取（core）**：环形缓冲、`peek_process_output`、结束后缩减、`ProcessStatus` 新字段，本地和远程一起。测试覆盖：中文和 emoji 跨块、跨页、跨淘汰边界；进程退出后管道才排空；两次读取之间写出超过一页就退出；100 个没读过的短命令结束 60 秒后的内存。
3. **监视和记录（web）**：监视任务、收尾函数、记录文件、清扫、`processes_changed` 事件、`/output` 和 `/log` 接口。这一步没有新界面。测试覆盖：进程退出后后代继续写输出，记录里要有后写的部分；带着运行中的 dev server 关闭会话，记录里要有已有的日志。
4. **面板（web）**：面板开关拆出、「后台」页、统一列表、命令详情、顶栏按钮的新状态、侧边栏指示；删除旧进程条和弹层。子任务行仍然打开完整对话。同步两份 README 和截图。
5. **子任务详情（core 一个字段 + web）**：`ChildSpec.spawn_id`、子会话的关联、步骤摘要、子任务详情、工具卡的链接。

实现时和设计的出入：`ProcessStatus` 多一个 `output_closed`（监视任务据此判断，不用为每个进程多一次调用）；`eof` 以管道关闭为准，缩减要等进程也退出；列表在有子任务运行且可见时，每 3 秒刷新一次步骤（没有事件告诉步骤变了），打开的子任务详情也是；`spawn_id` 写在 `spawn_subagent` 结果的文本里（`[spawn <id>]`），存在任务行的 `origin_ref`；停止一个正在执行工具的子任务时，界面显示「停止中」，直到工具返回、记录落定。

第 2 步是公开行为变化（`Workspace` 协议多两个方法，`ProcessStatus` 多字段）。1.0 之前，补丁版本直接改，不留兼容层。
