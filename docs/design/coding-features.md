## 不做和暂缓

| 项 | 决定 | 原因 |
| --- | --- | --- |
| 按轮文件回退（#146） | 暂缓，单独设计 | 只能在"本轮首次写某文件之前"留底；还要定新建文件的删除、回退前的冲突检查、shell 和子代理改动的覆盖范围、"一轮"与排队和 steer 的对应。Changes 面板的 HEAD diff 不能充当每轮备份 |
| 手动压缩 | 暂缓 | 使用频率低；要做时以"新增一条压缩决策"的方式实现，保持 view-only 和单调 |
| 计划模式 | 写成 recipe（#173） | "仅查看"模式加提示词即可 |
| 每个聊天一个 worktree | 暂缓 | 清理和合并的交互偏重 |
| LSP 诊断、系统级沙箱、配置式 shell hooks | 暂缓 | 分别需要管理语言服务进程、平台相关代码、与现有 Python hooks 重复 |
| 会话树、费用显示 | 不做 | 已有分支（#150 补"编辑即分支"）；token 环够用 |
| 全局 `AGENTS.md` 文件 | 不做 | 设置里每个 agent 的"自定义指令"已经是全局层 |
| 独立的提示模板目录 | 不做 | 一个模板就是一个 skill，不维护两套 Markdown 机制 |

## 1. 搜索遵守 Git 忽略规则

**现状。** `_walk_files`（`local.py:1066`，grep 用）和 `_list_matching`（`local.py:930`，带 `pattern` 的 `list_files` 用）只按隐藏路径和权限规则剪枝。`.gitignore` 写了 `node_modules/`、`dist/`，它们照样被遍历和返回。

**候选清单。** 新增一个内部函数，对目标目录返回"可搜索文件"的相对路径：

```text
git -C <base> ls-files --cached --others --exclude-standard -z
```

- `--others` 不能省：否则尚未 `git add` 的新文件搜不到。
- 清单里磁盘上不存在的条目（已删除未提交）跳过。
- 清单里磁盘上是目录的条目（submodule 的 gitlink、嵌套的独立仓库）：对该目录递归取候选，它们的内容不能从搜索里消失。
- 调用带超时（10 秒）。不是 Git 仓库、没有 `git`、非零退出、超时，都退回现有的 `os.walk` / `base.glob`。
- 清单里的每个文件仍要过现有的隐藏、权限（`_read_hidden`）、符号链接检查。

**grep。** `_walk_files` 有候选清单时按清单产出文件，顺序仍是排序后的路径。

**带 pattern 的 `list_files`。** 有候选清单时不再调 `base.glob`：

- 全集是"候选文件 + 它们的祖先目录"。这样正常目录（`pkg/`）仍然会被列出，被忽略的目录不会。
- 用一个小的 glob 转正则函数匹配相对路径（支持 `**`、`*`、`?`、`[...]`；Python 3.10 没有 `PurePath.full_match`）。先看 `workspace/rules.py` 的匹配器能否复用。
- 先过滤，再按 `max_results` 截断。
- 已知差异：Git 不跟踪空目录，空目录在这条路径下不再列出。

**点名被忽略的目录。** 不加新参数。目标目录本身被忽略时（`git check-ignore -q <base>`），按现状遍历：点名就是要搜。要全仓库连同忽略文件一起搜，用 shell。

**不变的部分。** 不带 `pattern` 的 `list_files`（单级，`_list_children`）和 Files 面板的浏览不过滤。

**测试。** 临时 Git 仓库：忽略目录不出现；未跟踪新文件出现；点名忽略目录能搜；`pkg/` 这类目录仍在 glob 结果里；submodule 和嵌套仓库的文件仍能搜到；无 `git` 时回退。

## 2. 分层 `AGENTS.md`

**现状。** `resolve_instructions`（`builder.py:299`）只读聊天目录里的 `AGENTS.md`。聊天开在 `repo/pkg` 时读不到 `repo/AGENTS.md`。

**规则。**

- 从聊天目录向上找 Git 根：第一个含 `.git` 的目录。`.git` 是文件也算（worktree、submodule）。
- 找到后，把 Git 根到聊天目录沿途每一层的 `AGENTS.md` 由外到内拼接，每段前一行标明来源路径。
- 没有 Git 根就只读聊天目录。聊天开在仓库根时，行为和现在完全一样。
- 顺序：agent 自定义指令 → Git 根 → … → 聊天目录。总大小沿用现有的 256 KB 上限。
- "编辑子目录时再加载子目录规则"不做。

**实现位置。** 发现和读取写成 `workspace/local.py` 里的一个标准库函数，和 `root_facts`（`local.py:184`）并列：本地由 `resolve_instructions` 直接调用，远程通过一个新的 session op 在远端执行。

**远程的权限边界。** 祖先目录的 `AGENTS.md` 是工作区外文件。走现有的 `session.read_bytes`，在"仅查看"模式下（`read_outside="deny"`）会被拒绝，本地和远程行为就不一致。所以新 op 是一条受限路径：

- 只读文件名在 `INSTRUCTIONS_FILES` 里、且位于根到 Git 根这条链上的文件，不接受调用方给的任意路径。
- 不看默认的 `read_outside` 判定，但显式规则（`denied_paths`、`path_rules`）照常生效：`policy.rule_bound(...)` 为真的文件跳过。注意 `_read_hidden(under_outside=True)` 不能直接用，它对默认 `deny` 仍返回隐藏（`local.py:503`）。
- 不放宽 `read_outside` 本身。

**稳定性。** 每个 run 读一次（沿用 `remote_instructions` 的闭包做法，`builder.py:345`），run 内前缀不变。

**展示。** 加载了哪些文件写进日志；UI 是否展示留到实现时看有没有现成的位置，没有就不加。

## 3. 编辑过期检查

**现状。** `edit_text`（`local.py:753`）已有精确匹配、重复匹配拒绝、按路径加锁、原子写入、编码和换行保护。缺的是：模型依据的读取结果是否已经过期。"读取 → 外部改了别处 → 编辑原片段"现在会成功。

**规则。**

- 会话上记 `解析后的绝对路径 → (mtime_ns, size)`。键和文件锁（`_lock_for`）用同一个路径，相对路径和符号链接不会形成两份基线。
- `read_text` 记录基线。基线必须对应实际读到的版本：在读内容之前取 `stat`，或者对打开的文件描述符 `fstat`；不能读完再 `stat`，否则会把刚发生的外部修改记成"模型已看过"。分页读取也记整个文件的基线。
- 自己的写入和编辑成功后更新基线。
- 检查放在 `write_bytes`（`local.py:707`，`write_text` 汇入这里）和 `edit_text` 的锁内：有基线且当前 `stat` 不一致就拒绝，提示重新读取。
- **读过的文件被删除也算变化**：即使这次 `write` 会变成"创建"，也拒绝，避免悄悄复活别人删掉的文件。
- **没有基线时放行**，包括覆盖一个从没读过的文件。这样服务重启、恢复 run 之后不会误报；`edit_file` 本来就要求精确原文。

**边界。**

- 元数据比对是尽力检测，第一版不上内容哈希。
- 会话锁只保护本会话。这项能发现此前的变化，不保证跨聊天的读改写互斥。
- web 默认路径下每个聊天、每个后台子代理各有自己的会话（`web/subagents.py:224`），基线不会被别的聊天刷新。嵌入式用法显式共享一个绑定会话时，基线也共享。
- 模型用 shell 跑格式化之后再编辑会被拒一次并重读，这是预期行为。

## 4. `/` 点名技能

**核心。** Skills 插件的系统提示（`plugins/skills/catalog.py:152`）加一句固定的话：用户消息开头的第一个 `/名字` 精确匹配一个可见技能时，先加载它。限定"消息开头""精确匹配"，避免前缀误匹配和把路径当成技能。这句话是静态文本，不影响提示缓存，CLI 同样生效。

**web。**

- 一个接口返回当前聊天可见的技能（名字、描述）。必须和运行时用同一个 catalog、同一套过滤和同名优先级。远程项目自己的技能目前不加载（#405，`builder.py:394`），接口不能把它们列为可用。
- 输入框行首打 `/` 弹出菜单，边打边过滤，选中后插入 `/名字 `。
- 发出去的就是用户看到的文本，服务端不展开。

**不包括。** 内置命令；`/review`、`/init` 在文档里给 skill 示例。`/compact`、`/undo` 是状态操作，不属于这一项。技能正文的预加载留给 #237。

## 5. `@` 引用文件

**语义。** 选中后在消息里插入 `@相对路径` 纯文本，只发路径，不发内容，模型自己用 `read_file` 读。没有新的权限和上下文大小问题。路径含空格时写成 `@"src/my file.py"`。

**候选清单的来源。** `_walk_files` 是 engine 的私有实现，web 不能跨远程调用它。走已有的 session 接口：`session.list_files(".", pattern="**/*", max_results=N)`，取其中的文件。第 1 项完成后它已经遵守 Git 忽略，且不再遍历 `node_modules`，本地和远程一致。

**web。**

- 一个接口返回路径列表和是否截断。`list_files` 已经过权限检查，接口不再绕开它。
- 浏览器按聊天缓存这份列表，在本地做模糊匹配。列表被截断后，继续输入也找不到没返回的文件，所以 `N` 取够大（先定 20000），截断时在菜单底部说明。
- 同一个接口用于 #385（Files 面板快速打开）。#386（引用选区）另做。

## 6. MCP 配置页

**配置。** `config.json` 加 `mcp` 列表，每项：名字、启用开关、stdio（命令、参数、环境变量）或 http（地址、请求头）。每个 agent 一个总开关，和 `search`、`memory` 同样的形式。`mcp` SDK 随 `lovia[web]` 安装。

**构建。** 启用的服务器在 `builder.py` 里变成 `MCP` 插件的条目，固定这些取值：

| 字段 | 取值 | 原因 |
| --- | --- | --- |
| `name` | 配置里的名字，必填且唯一 | 作为工具名前缀，避免多个服务器的同名工具冲突 |
| `auto_reconnect` | `False` | 现在遇到连接错误会重连并**重新执行同一个调用**（`plugins/mcp.py:402`）。服务器已经完成"创建 issue"而响应途中断线时，重放会创建两次；审批拦不住，因为重放发生在同一个已批准的调用内部 |
| `retries` | `0` | 同上 |
| `permission` | 每个工具：`"ask"`，带 `mcp:<工具名>` 授权范围；工作区 shell 默认放行（完全权限）时放行 | 核心默认是放行；MCP 工具可以改外部系统。完全权限下 shell 已能不经询问访问外部系统，再问拦不住什么 |
| `close_after_run` | `True`（默认） | 每个 run 连接一次，不引入常驻连接的生命周期管理 |

调用失败时错误信息要说明"操作可能已经发生"，由模型和用户判断下一步。

**已知代价。** 插件在 run 启动时就连接并列出工具（`plugins/mcp.py:809`），`defer=True` 只推迟 schema 的暴露。所以 `npx` 类服务器会让每条消息的启动变慢。先接受；确实慢了再改成应用级常驻连接。

**单个服务器不可达。** 核心现在会让整个 MCP setup 失败，run 也就失败。web 里改为：跳过这个服务器，run 继续，并在聊天里明确提示哪个服务器没连上。初始化要有超时。

**权限模式的说明。** 文档和 UI 都要写明：工作区的"仅查看"只约束文件和 shell，不约束 MCP 工具对外部系统的操作；后者靠默认询问（完全权限除外）。

**设置页。**

- 一页列出服务器，每行显示**最近一次测试的结果、时间、工具数**。按 run 连接时没有"持续在线"这回事，不这样称呼。
- 新增和编辑用一个 JSON 文本框，接受通行的 `mcpServers` 写法。
- "测试"按钮：连接、列出工具、关闭，带超时。

**密钥。** `env` 和 `headers` 里的值在接口返回时打码。保存时沿用模型 API key 的约定（`web/api/config.py:65`）：未改动的打码值保留原值，空字符串清除，其他字符串替换。不能把打码占位符写回配置。

**实现补充（#438）。**

- 每行的“最近一次连接”除了来自“测试”按钮，也来自每个 run 的连接；保存后自动测试刚保存的服务器。这些状态只在内存里，重启后清空。
- 聊天里的提示是一个只在实时流里出现的 `mcp_unavailable` 帧（刷新后不重放）；同时在系统提示里告诉模型哪些服务器没连上。
- 后台子任务不挂 MCP：没有人在场批准它们的调用。
- 核心 `MCPConnection` 在不重连时遇到连接中断，错误信息改为“调用可能已经生效，也可能没有”。
