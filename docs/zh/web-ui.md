# Web UI

Web UI 是 lovia 自带的本地聊天应用，适合直接使用 Agent，或在开发自定义前端前验证功能。

## 一条命令启动

```bash
pip install "lovia[web]"
lovia web
```

访问 `http://127.0.0.1:8000`，首次启动时配置一个模型即可。之后可用
`lovia web --check` 检查配置并探测端点，而不启动服务。

服务保存的一切都在一个目录里，即 lovia 的 **home**——默认 `~/.lovia`，`--home DIR`
可以换成别处。启动目录里的东西一概不读，它只决定新对话默认在哪个目录工作：

| home 里的 | 内容 |
| --- | --- |
| `config.json` | 模型、Web 搜索、全局技能目录、MCP 服务器，以及[助手的设置](#助手) |
| `lovia.db` | 聊天记录（`--db FILE` 可放到别处） |
| `memory/` | 长期记忆：关于你的笔记，`scopes/` 下按项目分开的笔记和历史 |
| `workspace/` | 不属于任何项目的对话的工作区 |

互不相干的环境——一个测试实例、不同的客户——各用一个 `--home`。在支持 Unix 权限的平台上，
home 只允许当前用户访问，里面还放了一个内容为 `*` 的 `.gitignore`，所以放在仓库里的 home
不会被提交。home 必须是 lovia 专用的目录：仓库根目录，或者 `.gitignore` 没有忽略全部内容的目录，
会在写入任何东西之前被拒绝。

0.9.179 之前，启动目录里的 `./.lovia/config.json` 会整体取代用户的配置，那里已有的
`./.lovia/lovia.db` 会被沿用，记忆默认放在 `./.lovia/memory`。这些现在都不再读取；
`lovia web --home ./.lovia` 与以前在那个目录启动的行为完全一样。没有传 `--home` 而启动目录里有
`./.lovia/config.json` 或 `./.lovia/lovia.db` 时，服务会打一行日志说明这一点（后者还会说明如何把那些对话移到
home 里）。

CLI 创建的默认 Agent 包含 Todo、Memory、时间与 HTTP Tool、Web 搜索、定时任务，以及以
当前目录为根的 coding 模式 Workspace。它每次运行都从对话所在的目录读取：

- `AGENTS.md`：作为 Agent instructions，见[下文](#项目指令)；
- `.agents/skills`：项目自己的技能，排在全局技能目录（默认 `~/.agents/skills`，在设置 → 技能中管理）之前。

所以在另一个项目里的对话会遵循那个项目的 `AGENTS.md` 和技能。

网页搜索通过 MCP 调用一个托管的搜索服务，在**设置 → 联网搜索**中选择：自动（默认）、Parallel、
Exa 或 Tavily，都能在免费额度内免 key 使用；在"高级"里填了 API key 后，搜索算在你在该服务的账户上，
可能按量计费；也可以关闭。自动先问 Parallel，只有连不上（比如被所在网络拦截）才依次换 Exa、Tavily；
已经答复的（包括额度用完）不会再转给别家，答复的那家在之后十分钟里优先。搜索走不走代理默认按
设置 → 通用 → 系统代理，也可在"高级"里单独设置。选中即保存并立即测试连接（不消耗搜索次数）；页面会写明搜索词
发给了谁，自动时显示由哪家答复。无论选哪家，工具形状都一样；只在模型真正搜索时才连接，不搜索的
消息不受影响。Exa 的免 key 额度会拒绝部分代理出口，那时请直连或填 key。别的搜索服务可以在
设置 → MCP 中添加（同时把这里设为关闭）。

默认功能会产生主 Run 之外的模型调用：标题和追问建议各自独立调用，`recall` 检索过往对话时
也会调用（Memory 没有其他调用模型的地方）。可以在**设置 → 助手**里关闭长期记忆或追问建议，
或把辅助任务指派给更便宜的模型。Memory 的完整成本边界见[记忆](memory.md#使用建议)。

!!! danger "默认仅供本机使用"

    回环地址 `127.0.0.1` 默认不鉴权。绑定其他地址时必须设置 `--token` 或
    `LOVIA_WEB_TOKEN`；未设置时服务会自动生成。持有 token 的客户端可以使用 Agent 的
    全部能力，包括编辑文件、执行 Shell 命令、打开其他目录和远程工作区——除此之外绑定地址不改变
    任何行为，因此应把 token 当作密码。允许其他设备访问时，用 `--readonly`、`--lock-workspace`
    或 `--no-workspace` 收紧；多用户部署请参阅[生产部署](deployment.md)。

### 项目指令

在 Git 仓库里，对话会加载从仓库根（向上第一个含 `.git` 的目录，worktree 或 submodule 的 `.git` 文件也算）
到对话目录沿途的每一个 `AGENTS.md`，由外到内排列。不在仓库里时只加载对话目录自己的 `AGENTS.md`。
这些文件接在助手自己的提示词之后，前面有一段简短说明：冲突时以更深一层的文件为准，用户的要求优先于所有文件；
每个文件包在一个 `<project_instructions path="…">` 标签里。加载了哪些文件会写进日志。

- **大小。**合计 256 KB，从对话目录往外装：装不下的文件整份跳过，日志里会写明是哪个。
- **权限。**这些文件是项目的指令，不是 Agent 去探索的内容，所以权限模式对"读取目录之外"的默认判定不适用：
  "仅查看"模式下照样加载对话目录之上的仓库规则。显式规则照常生效（内置的凭据目录、服务自己的 `config.json`、
  部署方配置的禁止路径），并且按文件的符号链接实际指向的位置判定，指向密钥的 `AGENTS.md` 会被跳过。

## 模型配置与切换

模型档案保存在 `config.json` 中，在**设置 → 模型**里编辑；Web 搜索服务有单独的一页，**设置 → 联网搜索**。连接测试会真实检查端点可达性、认证、模型列表和上下文窗口；
端点未列出的模型 ID 仍可手动填写。

API Key 只写不读：服务端只返回是否已设置及脱敏提示，不会把完整密钥传回浏览器。配置更新会
整体校验、原子写入并立即生效，无需重启。

每个对话用自己的模型。输入框里的模型按钮选的就是它：新对话在发第一条消息前选，已有对话从
**下一条消息**开始生效，正在进行的回复仍用原来的模型完成。对话记录与 provider 无关，所以中途可以换，
代价是 provider 的提示缓存从头再来。设置 → 模型里的**设为默认**决定对话在自己选之前用哪个：
新对话、从没选过的对话，以及所选模型已被删除的对话。后台子 Agent 和定时任务新开的对话使用默认模型。视觉理解以及标题、追问建议等辅助任务，可以分别指派给其他模型档案。

**系统代理**（高级）决定发给这个模型的请求是否经本机配置的代理：**跟随全局**按 设置 → 通用 →
系统代理 走，**直连**忽略代理，**经代理**走代理（`HTTP(S)_PROXY`，没有时用系统代理），绕过列表里的
主机和本机地址直连，和浏览器一致。
**测试**按表单当前的选择进行；测试或对话失败时，会说明是跳过了代理还是被代理挡住了。

**额外请求参数**（高级）是一个 JSON 对象，原样合并进发给该端点的每个请求——即 provider 的
[`extra_body`](providers.md#extra_body连接级的请求字段)。推理相关的配置就靠它，按端点自己的
写法填，因为一个 OpenAI 兼容格式背后藏着许多方言：OpenAI、DeepSeek、Qwen 3.8 和 vLLM 用
`{"reasoning_effort": "medium"}`；vLLM/SGLang 部署的 Qwen、GLM 用
`{"chat_template_kwargs": {"enable_thinking": false}}`；DeepSeek 与智谱官方 API 用
`{"thinking": {"type": "disabled"}}`；Anthropic 用 `{"output_config": {"effort": "medium"}}`。
值为 `null` 表示删除适配器本来会发的字段（拒绝 `stream_options` 的网关可写
`{"stream_options": null}`）。不做任何转换，端点接受什么由端点决定——官方 API 会在下一条消息
时拒绝不认识的字段，vLLM 则可能静默忽略；对话里有没有思考痕迹才是真正的检验。编辑框下方的
快捷片段只负责写入这些形状，不代表模型支持。

经过这个档案的每一次调用都会带上这些字段——主回复、后台子 Agent、上下文压缩摘要，以及被指派为
视觉或辅助角色时的图片描述、标题和追问。同一端点想要第二套参数，就是第二个档案：**复制**在服务端
完成（连密钥一起，因为页面从不持有它），所以"标题不思考"就是复制一份、写上
`enable_thinking: false`、指派给辅助角色。思考模型需要输出空间：可以在档案的高级选项里设置
**最大输出 tokens**（额外字段里的 `max_tokens` 优先于它）。它限制用这个档案的对话回复和后台子 Agent，
不限制标题、追问建议和图片描述；上下文策略的输出预留也不会跟着变。

搜索服务、它的 key 与 Skill 目录也保存在 `config.json` 中。模型连接、多模型档案、
角色指派、搜索和 Skills 配置没有对应的 CLI 参数；请通过设置页或直接维护配置文件。

## Skills

技能从两处加载；每个 skill 是含 `SKILL.md` 的子目录（详见 [Skills](skills.md)）：

- **项目自己的** `.agents/skills`，位于对话所在目录的根下。它和 `AGENTS.md` 一样是约定，
  不是配置项：在该项目的每个对话里自动加载，重名时优先。远程工作区里的对话暂时拿不到项目的技能。
- **全局目录**，在设置 → 技能中管理——一个有序列表，只接受绝对路径或 `~` 开头的路径，
  对所有对话都一样；重名时靠前的目录优先。默认是 `~/.agents/skills`；移除它即禁用，
  也可以添加任意其他目录。相对路径会被拒绝，因为它在每个对话里指向不同的目录
  （已保存文件里旧的 `.agents/skills` 条目会被丢掉：它本来就会加载）。

面板只列全局目录，并展示每个目录的贡献——发现的 skills、解析问题、被遮蔽的重名项；
不存在的目录会被直接跳过，过期条目不会阻止服务启动。列表变更立即生效；向已配置的目录里
新增 skill 则无需任何操作。

在输入框的最开头打 `/`，会弹出这个对话能用的技能，边打边过滤；↑/↓ 选择，Enter 或 Tab 插入
`/名字 `，Esc 关闭。列表和这个对话的 run 实际加载的完全一致：项目技能和同名优先级
都算在内，远程对话只列全局目录里的。发出去的就是输入框里的文字，模型按
[`/名字` 规则](skills.md#按名字调用-skill)自己加载。消息中间或第二行起的 `/` 不弹菜单——
模型也只认消息开头的那一个。

### 斜杠命令

同一个菜单里，**命令**排在技能前面。命令由页面执行，不会发给模型。内置的只有几个：输入框旁边一点就到的东西（模型、权限模式）
没有对应的命令。

| 命令 | 作用 |
| --- | --- |
| `/review` | 让助手审查已暂存和未暂存的改动及相关的未跟踪文件，按优先级报告问题，不修改文件 |
| `/branch` | 从这个对话分出一个新对话 |

命令只在适用的地方出现（有工作区才有 `/review`，对话可分支时才有 `/branch`）。选中就执行。
命令和技能重名时，命令优先。自己的页面可以
[添加命令](web-server.md#命令)。

## 助手

`lovia web` 只有一个 Agent `lovia`。**设置 → 助手**决定它在所有对话里怎么工作：自定义指令、新对话的权限模式和
免确认命令，以及四个开关（网页搜索、长期记忆、后台子任务、追问建议）。项目之间的差别来自项目自己——它的
[`AGENTS.md`](#项目指令)和 `.agents/skills`；对话之间的差别在输入框下方选（目录和权限模式）。

- 最大轮数和重试次数不在设置页里：在 `config.json` 里改 `assistant.max_turns`（200）和
  `assistant.max_retries`（5），重启后生效。助手页会显示当前的值和文件路径。0.9.289
  之前在设置页保存过的文件写的是旧默认值 `150`，你改之前一直按它来。
- 长期记忆按项目分层（见[记忆的作用域](memory.md#作用域)）：关于你的笔记只有一份，
  每个项目的对话都带上；关于项目的笔记和历史对话检索按对话所在的目录分开，**对话**分组（不属于任何项目）里的对话只有前一层。
  在**设置 → 记忆**里选要编辑的范围："关于我"，或从列表里选一个项目，默认是当前对话所在的目录。
  **清空该项目记忆**会删掉这个项目的笔记和历史对话检索，
  不可撤销；删对话不会顺带清记忆。
  按目录识别项目，目录改名或移动后项目记忆就断开了。更早版本存下的笔记都留在"关于我"，里面关于某个项目的条目可以手工挪到那个项目；
  更早的历史对话检索留在顶层，只有**对话**分组里的对话还搜得到。

`config.json` 里没写的字段取默认值（见[下文](#不用重启的设置)）：

```json
{
  "version": 3,
  "assistant": {
    "instructions": "先给结论。",
    "mode": "coding",
    "max_turns": 300
  }
}
```

!!! note "从 0.9.207 及更早版本升级"

    更早的版本把这些设置放在别处：第 1 版在 `agent`、`run`、`workspace` 三段里，第 2 版在 `agents` 列表里
    （可以有多个 Agent，各有一份）。两者都不会折算：助手从默认值开始，下次保存时写成第 3 版。
    模型、角色、搜索、技能和 MCP 服务器照常保留。存在别的 Agent 名下的对话由 `lovia` 继续；
    存在别的 Agent 名下的定时任务会失败并说明原因，需要重建。

## MCP 服务器

**设置 → MCP** 列出对话可以使用其工具的 [MCP](mcp.md) 服务器。
添加时直接粘贴其他客户端通用的 `mcpServers` JSON，一次可以加多个：

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/dir"],
      "env": { "SOME_TOKEN": "…" }
    },
    "docs": {
      "type": "http",
      "url": "https://example.com/mcp",
      "headers": { "Authorization": "Bearer …" }
    }
  }
}
```

服务器要么是在 lovia web 所在机器上运行的 `command`（stdio，远程对话也一样），要么是一个 `url`（streamable HTTP，不支持 SSE）。
服务器名会作为它的工具名前缀（`docs__search`），只能用字母、数字、`-` 和 `_`。两个服务器拼出同一个工具名时（`a` 的 `b__c` 和 `a__b` 的 `c`），后连上的那个工具不挂载。命令可以用 `cwd` 指定启动目录。`"disabled": true` 表示保存为停用。其他字段会被忽略。

编辑框里只有一个服务器时，下面有两个**选项**，点选会改写 JSON 里对应的键，手写这些键也一样：

- **工具定义**：“全部加载”（默认）每次都把这个服务器所有工具的定义发给模型；“按需加载”（`"defer": true`）只在提示词里列出工具名，模型用到时先用 `search_mcp_tools` 查定义，再通过 `call_mcp_tool` 调用。适合工具多的服务器：每个 run 照样连接服务器、列出工具，省下的是没用到的那些工具的定义。审批和“总是允许”都按目标工具算，和直接调用一样。
- **系统代理**（只对 url）：“经代理”/“直连”（`"trustEnv": true` / `false`）表示经系统代理连接或不经，不受 设置 → 通用 影响；“跟随全局”不写这个键。连接失败时会说明是跳过了代理还是被代理挡住了。

- **每条消息连接一次。** 每个 run 开始时依次连接这些服务器，结束时关闭，run 之间不保持连接。`npx` 类服务器会让每条消息的启动慢一些。
- **每次调用工具都会先问你**，“完全权限”除外：“仅可查看”和“工作区内修改”只管文件和 shell，管不到 MCP 工具对外部系统的操作；
  而“完全权限”下 shell 本来就能不经询问地访问这些系统（`curl`、`gh`），再问也拦不住什么。
  审批卡片可以选“本对话中总是允许”这个工具，和命令一样。
- **不重放调用。** 调用过程中连接断开就算失败；服务器可能已经执行了，错误信息会这样说明，而不是自动再调一次。
- **工具返回的图片会显示出来。** 浏览器类服务器的截图会出现在工具卡片上，并[以图片的形式交给模型](mcp.md#mcp-工具的运行方式)。
- **连不上的服务器会被跳过。** 每个服务器有 30 秒启动并列出工具；超时或出错时，run 不带它继续，
  聊天里会显示哪个服务器没连上、原因是什么，模型也会知道。
- **每一行显示最近一次连接的结果**（来自 run 或“测试”按钮）：成功与否、时间、列出的工具。“测试”会立即运行服务器的命令；
  保存后会自动测试刚保存的服务器。这些结果只保存在内存里，重启后都显示“还没连接过”。
- **密钥默认隐藏。** `env` 和 `headers` 的值返回时会打码（`ghp…a1b2`）。在编辑框里，打码的值不改就保持原值，清空表示删除，
  填新值则替换；对不上任何已保存值的打码值会被拒绝。点**显示密钥**会把已保存的值填进编辑框，便于查看或复制（只在这时
  获取，需本机访问或带令牌）；**隐藏密钥**再把它们打码。`command`、`args` 和 `url` 会原样显示，
  所以令牌应放在 `env` 或 `headers` 里，不要写在参数或 URL 的查询串里。

MCP 支持随 `web` 扩展一起安装。服务器保存在 `config.json` 的 `mcp` 里。
后台子任务不带 MCP 工具：没有人在场批准它们的调用。

### 项目自己的服务器

对话还会读取它所在目录根下的 `.mcp.json`——其他客户端读的也是这个文件，随项目一起提交：

```json
{
  "mcpServers": {
    "db": {
      "command": "npx",
      "args": ["-y", "@example/db-mcp"],
      "env": { "DSN": "${APP_DSN}" }
    }
  }
}
```

它和 `AGENTS.md`、`.agents/skills` 一样是约定，不是设置项：lovia 只读这个文件，从不写它。但它写的是要运行的命令，
而且是随仓库来的，所以**其中的服务器在你打开之前不会启动**：

- 设置 → MCP 有两个范围。**单个项目**列出那个项目的服务器：`.mcp.json` 里的在**项目自带的**下面，
  每个都有条目原文和一个开关；然后是你自己添加的。
- 只要还有待确认的，输入框上方会有一行提示，点**查看**就打开这一页。对话照常进行，只是不带这些服务器，
  不会等你回答。
- 决定保存在 lovia 的 home 里（`mcp-projects.json`），按项目目录分开，不放在项目里：仓库不能自己批准自己。
- 决定只对当时的条目有效。条目被改过——拉了新代码，或者 Agent 改了文件——就要重新决定。
- `command`、`args`、`env`、`url`、`headers` 里的 `${VAR}` 和 `${VAR:-默认值}` 在运行开始时用服务进程的环境变量填入，
  所以密钥不必写进文件。用到了没设置（也没有默认值）的变量的条目不会启动，页面上会说明是哪个变量。
- 命令在项目目录下启动；条目写了 `cwd` 时，相对项目目录解析。和设置里的服务器重名时，用项目的这一个。
  写了 `"disabled": true` 的条目会列出来，但不能打开。
- 这个决定只能由你来做：任何权限模式下，Agent 的文件工具都打不开 `mcp-projects.json`，提到它的 shell 命令也会被拒绝，
  和 `config.json` 受到的保护一样。（“完全权限”下任何程序都不经询问就能运行，那个模式本来就是把这台机器交给 Agent。）
- 定时任务和其他运行一样，只用已经打开的。在另一台机器上工作的对话（[远程工作区](#工作区)）不读这个文件。

打开之后，它的工具和其他 MCP 工具一样：除“完全权限”外，每次调用前都会先问。

### 只给一个项目用的服务器

**单个项目**范围里也列出你自己添加的服务器，每个都有一个只对*这个项目*生效的开关：

- 对所有项目关着的服务器可以在这里打开，开着的可以在这里关掉。其他项目和**所有项目**范围都不变。
- **添加到这个项目**添加的服务器只给这个项目用：和其他服务器一样保存在 `config.json` 里，保持关闭，
  只在这里打开——不会往项目里写任何东西。在**所有项目**范围里它显示为“仅 1 个项目”。
- 项目没有单独设置时，跟随服务器自己的开关，之后改了也跟着变。
- 这些是你自己添加的条目，所以不需要批准；记录在同一个 `mcp-projects.json` 里。
- 在另一台机器上工作的对话也有这些开关：服务器仍然运行在 lovia web 所在的机器上。**对话**分组（不属于任何项目）里的对话跟随**所有项目**。
- 打开的服务器越少，这个项目的对话每次请求带的工具就越少——每个服务器的工具不管用不用都会发给模型。

## 加载自定义 Agent

创建 `app.py`：

```python
from lovia import Agent

assistant = Agent(
    name="assistant",
    instructions="清晰回答，并在有助于提高准确性时使用工具。",
    model="<model>",
)
```

然后运行：

```bash
lovia web --app app:assistant
```

`--app MODULE:ATTR` 接受一个 Agent、`{name: agent}` 映射，或由 `create_app()` 构建的应用
（也可以是返回其中任意一种的无参工厂函数）。应用会按构建时的配置原样运行，沿用自定义的认证、
存储和 UI 选项；CLI 仍负责 host、port、日志和启动信息。原本会传给 `create_app()` 的选项
（`--token`、`--db`、`--title` 等）会被忽略并给出警告。Python 部署和 ASGI 集成详见
[Web 服务端](web-server.md)。

想保留本页的全部功能，再加点自己的东西——一个工具、一个插件、自己的鉴权——就在代码里用
[`default_app()`](web-server.md#两个入口) 构建同一个应用，再托管它。

界面支持 GitHub 风格 Markdown、代码高亮、Mermaid 和内嵌图片。默认 Agent 已知道这些能力；
自定义 Agent 不会自动获得相关提示。如果希望模型主动使用这些格式，可以加入 `SURFACE_NOTE`：

```python
from lovia.web import SURFACE_NOTE

assistant = Agent(
    name="assistant",
    instructions="清晰回答。\n\n" + SURFACE_NOTE,
    model="<model>",
)
```

## 图片与文件

附件属于对话，不属于项目：它存在对话自己的目录里，和聊天记录放在一起——数据库旁边的
`attachments/<id>/`，`lovia web` 下就是 `~/.lovia/attachments/`——从不写进 Workspace，
所以 Git 仓库保持干净。消息里用绝对路径指明每个文件，对话的 run 可以读取。因此即使模型不能直接
读取附件，Agent 仍可通过 Workspace Tool 打开文件；需要放进项目时，让 Agent 复制一份即可。任何权限
模式下都禁止写入这个目录——文件工具和 shell 重定向（`>`）都写不进去。和所有路径规则一样，这是一道
防护，不是沙箱：自己改写文件的 shell 命令（`sed -i`、`rm`）只按字面判断，它们的参数会被当作读取；
要让目录真正只读，需要沙箱执行器。在远程主机上工作的对话，读的是主机上的一份副本，同样不在工作区里——放在主机
临时目录下一个只有该账号能进入的目录（Linux 上是 `/tmp/lovia-<uid>/attachments/`），规则相同。这些副本只是缓存：
每次运行和每条消息都会把主机上缺的补回去，由系统清理临时目录时删除；删除对话只删本机上的原件。
没有工作区时（`--no-workspace`，或者构建时就没给 Agent 工作区），没有文件工具可以读取附件，所以只接受图片
（PNG、JPEG、GIF、WebP），并且只在模型能看图时才可用：图片直接发给模型，输入框也只允许选图片。

fork 出来的对话和对话的子任务共用同一个目录，所以源对话删除后，fork 仍能显示它历史里提到的附件。
最后一个使用该目录的对话删除时，目录随之删除；草稿里上传了却没发出去的文件，一天后清理。
几个数据库放在同一目录时（`create_app` 默认的 `.lovia/<agent>.db`）共用 `attachments/`，
每个库只删自己的对话在用的、或者自己建的目录，目录里的 `.lovia-owner` 文件标明归属。
0.9.287 之前建的、已经没人用的目录没有这个标记，会保留下来。

Markdown 图片可以直接引用 Workspace 内的文件——`![chart](charts/q3.png)` 会显示该文件本身，
回复和文件面板的 Markdown 预览都是如此。路径先按文档自身所在目录解析，再按 Workspace 根目录解析；
读取走的是与预览相同的只读接口。SVG 也能显示，走的是该接口的附件形式：浏览器对图片子资源会忽略
`Content-Disposition`（此时 SVG 里的脚本被禁用），对导航则会遵守（此时脚本本会执行）——于是图能显示，
而 URL 本身只会下载。

链接（`[report](report.md)`）指向同一个接口：在回复中，浏览器能直接显示的文件（图片、PDF）会在
新标签页打开，其余文件直接下载，对话本身不会被导航掉；在文件面板内，同样的链接则在查看器中打开。

输入框为空时按 ↑，会从最近一条开始依次填入这个对话里发过的消息，可以再发或改一改；按 ↓ 往回翻，直到清空。

想让 Agent 看某个文件又不想上传，可以在消息开头或空格后面打 `@`：输入框会列出对话目录里的文件，
边打边匹配——先匹配文件名，再匹配目录，最后按字母顺序模糊匹配。↑/↓ 选择，Enter 或 Tab 插入
`@路径 `，Esc 关闭。路径里有空格时会加引号，写成 `@"docs/my notes.md"`；含双引号、换行或其他
控制字符的路径不会列出（需要时手动输入）。发出去的只有路径本身，原样发送——模型自己用 `read_file`
打开，所以权限和上下文大小都不受影响。

列表就是 Agent 自己的 `list_files` 能看到的：在 Git 仓库里遵守仓库的忽略规则，不含点开头的文件，
也不含 Workspace 的 `denied_paths` 屏蔽的文件；远程对话列的是远端主机上的文件。
浏览器按对话缓存这份列表，每个 run 结束后重新获取，所以 Agent 新建的文件也能搜到。列表最多约
20000 条；超过时菜单底部会说明列出了多少个文件，其余的可以直接输入路径。
回复里的外部链接同样在新标签页打开。

附件图片会保存在对话里并发给模型：

- 所有模型默认按能看图处理。不收图的模型，把该模型配置的视觉能力设为“不支持”
  （即 `config.json` 中的 `"vision": "off"`）：之后每张图片的位置发给它的是一行说明文字，
  对话换成能看图的模型后，这些图片照常可见。模型拒收图片时这次回复会失败，报错里有指向
  这个设置的提示。
- 设为“不支持”的主模型可以把视觉角色指派给另一个模型配置，再通过 `describe_image` Tool
  获得图片的文字描述。

单个文件默认不超过 25 MiB，可用 `LOVIA_MAX_UPLOAD_MB` 调整。带扩展名的文件受内置白名单限制；
`LOVIA_UPLOAD_ALLOWED_EXT` 可覆盖白名单，使用逗号或空格分隔，`*` 表示不限。

右侧面板有**变更**、**文件**、**后台任务**三个页签。顶栏的文件夹按钮打开前两个中上次用的那个（第一次是变更），
顶栏的运行状态按钮打开后台任务。每个页签各自记住打开的东西：变更里的 diff、文件里的文件、后台任务里的日志，
切走再切回来还在。变更页签上显示本对话写过的文件共增删多少行（`+12 −3`，面板太窄时省略），后台任务页签上显示正在运行的数量。

**变更**列出本对话写过的文件，加上作为消息附件的 Workspace 文件，按修改时间倒序。
在 git 仓库里还有一组默认折叠的"其他未提交改动"，列出 `git status` 在该目录下看到的其余改动；
每一行带增删行数（`+12 −3`）或"新文件"标记。已跟踪且有改动的文件打开时显示相对上次提交的
diff，旁边的"文件"标签切到文件本身；新文件直接显示文件。不在 git 仓库里时只有本对话一组，
也没有 diff。git 在存放文件的主机上执行，只允许 `git rev-parse`、`git status`、`git diff`
三条命令；Agent 不经询问就读不到的路径不会出现。

**文件**是目录树：文件夹原地展开；只含一个子文件夹的文件夹连成一行显示（`src/app/core`）；
展开的文件夹在其内容滚动时停在顶部。方向键可在树中移动。打开文件后，"⋯"菜单可在树中定位该文件。
超出工作区列表上限（`max_list_results`）的文件夹只列出上限数量的项目，并注明还有更多。

浏览器和 lovia web 在同一台机器上时（loopback、没有 token），文件行的右键菜单、打开文件后的"⋯"
菜单和侧栏项目菜单里还有**在 Finder 中显示**（资源管理器；Linux 上是打开所在文件夹），文件还有
**用编辑器打开**：该类型的关联应用是代码或文本编辑器（VS Code、Cursor、Zed、JetBrains 系列、
Sublime Text 等）时用它，否则用系统的纯文本编辑器——会被执行的 `.sh`、`.py` 也改用文本编辑器打开。
"用编辑器打开"只在 macOS 和 Windows 上提供；远程主机上的对话两者都不显示。

文件面板是只读的，没有上传。要把文件放进项目，可以自己复制到目录里，或者作为附件发出去、让
Agent 保存。变更列表不列 Agent 的临时目录 `tmp/`，"新文件"角标也只统计会出现在列表里的写入——
这只是展示规则：目录浏览显示所有目录，Agent 引用的任何路径（回复里 `tmp/` 下的图片、工具卡片的
"在文件面板打开"）只要 Agent 自己能读就能打开。0.9.239 之前的对话把附件放在 Workspace 的
`uploads/`；那些消息照样显示附件，这个目录也不会被移动或删除。

### 后台任务

右侧面板的**后台任务**页列出这个对话背后正在跑和跑过的东西：[子任务](#后台子-agent)，以及 Agent 用
`shell(background=true)` 启动的命令（开发服务器、测试等）。命令以 Agent 给它写的说明为名，没写时显示命令本身。等你处理的排在最前，已结束的折叠在下面。
顶栏按钮显示正在运行的数量（红点表示有你还没看过的失败），点击打开这一页；有命令在跑的对话，在侧栏
带一个空心圆点。没有 Workspace 的 Agent 只有这一个页签。

点一条命令，或点它工具卡上的*查看输出*，可以看日志：命令运行时跟随输出，也可以放大查看。面板里显示
最新的 5000 行，下载能拿到保留的全部。查看日志不会影响 Agent 自己读取输出；你停止命令后，Agent 会收到
提醒，并能读到剩下的输出。停止子任务要再点一次确认：它会就此结束，也不再有报告。点子任务，或点它 `spawn_subagent` 工具卡上的*查看子任务*，可以看到任务说明、当前步骤和最终报告；*打开完整对话*能看到全部过程。

后台进程属于聊天而不是单次 Run：Run 结束不会终止它们；删除聊天或停止 Web 服务时会统一清理，
服务重启后也不会恢复。更完整的生命周期见[工作区](workspace.md#后台进程)。

进程结束后，输出会留下记录，存在聊天数据库旁边的 `process-logs/`：一个进程一个文件，每个对话保留最新的
30 条，随对话删除。每个数据库的记录总量限制为 300 MB（`LOVIA_MAX_PROCESS_LOGS_MB`），超出时先删最旧的。
它们只是缓存：整个目录可以随时删掉，对话里只是不再显示历史记录。

### 附件须知

使用 `lovia web` 时：

- **项目保持干净。**附件存在 `~/.lovia/attachments/`（和聊天记录在一起），从不放进对话所在的目录。
  0.9.239 之前的版本留下的 `uploads/`，可以自己删掉或忽略。
- **附件跟着对话走。**删除对话时，只要没有它的 fork 或子任务还在用，附件就一起删除；没发出去的草稿附件一天后清理。
- **Agent 能读附件，但不会改它。**要把附件放进项目，让 Agent 存过去即可。项目里已有的文件用 `@路径`
  引用，不用上传。
- **远程对话会在主机上留一份副本**，不在项目里，而是在一个只有你在那台主机上的账号能进入的目录。删除对话
  不会删这份副本，要等主机清理临时目录——敏感文件要留意这一点。
- **没有工作区时**只能发图片（PNG、JPEG、GIF、WebP，不超过 10 MB），而且模型要能看图；附件按钮跟着对话
  所选的模型显示或隐藏。

基于 `lovia web` 构建应用（`create_app`、多用户应用）时：

- **存放位置跟着 `ChatStore` 走**：在它的数据库旁边的 `attachments/` 里。每个用户一个 store，附件就按用户
  隔离；删掉用户目录，附件一起删掉。要放到别处，用 `ChatStore(..., attachments_dir=...)`。
- **接口**：`POST /api/sessions/{id}/attachments` 和 `GET /api/sessions/{id}/attachments/{name}`
  （见 [HTTP API](http-api.md)）。新对话由页面在第一次上传前生成 32 位十六进制 id，发送时沿用它；页面只看得到
  文件名。
- **给 Agent 传工作区配置，不要传绑定好的 session。**`LocalWorkspace` 或 `RemoteWorkspace` 接收任意文件；
  绑定了你自己打开的 session 的 Agent 不接收上传，因为那一个 session 被所有对话共用。没有工作区的 Agent
  在模型能看图时接收图片并直接发给模型——`/api/agents` 会报告 `vision`，`"vendor:model"` 字符串也会先解析
  再判断。
- **每次运行都会加上附件目录的两条规则**——能读、不能写，handoff 的目标也一样。你设的 `denied_paths`
  优先：如果它屏蔽了数据目录，工具就读不到附件（图片仍会直接发给模型）。自定义的工作区后端没有可加入规则的策略。
- **限制是整个进程共用的**（`LOVIA_MAX_UPLOAD_MB`、`LOVIA_UPLOAD_ALLOWED_EXT`），同一个服务器暂时没法按用户分别设置。

## 图表

`show_chart` 工具可以在聊天中绘制交互式图表，支持折线、柱状、饼图、散点、热力图、K 线、
桑基图等 [Apache ECharts](https://echarts.apache.org/) 的系列类型。模型把 ECharts option
写成调用参数，卡片负责渲染；实时对话和重新打开会话时都会显示。`lovia web` 的默认 Agent
已带有这个工具；使用自己的 Agent 时，把工具加进去：`tools=[show_chart]`（从 `lovia.web` 导入）。任何工具也都
可以产出图表：`return ui_result("chart", option)`，直接用真实数据作图，不需要模型抄写数字
（见[UI 组件](web-server.md#ui-组件)）。如果工具的 option 来自模型（比如执行查询后把结果行放进
option 的 `dataset`），先用 `validate_chart_option(option)` 检查：它抛出与 `show_chart` 相同的
工具错误，模型可以据此修正 option 后重试。

图表标题显示为卡片标题，位于图表上方，不会与图例重叠。标题旁的工具栏（鼠标悬停时显示）可以
把图表下载为 PNG 或 SVG（包含标题）、把数据下载为 CSV（树图、桑基图、关系图没有表格结构，
下载为 JSON），也可以全屏查看。

须知：

- ECharts（约 1 MB，已随包内置）在出现第一张图时才加载，没有图表的会话不会请求它。
- 把聊天导出为 HTML 时，每张图表以 SVG 图片的形式包含在内。
- option 在绘制前会经过过滤：图片、链接、`graphic` 和 `toolbox` 组件、HTML 形式的
  tooltip 都会被去掉；需要代码或地图数据的系列类型（`custom`、`map`）也不支持。
- 团队的作图约定（偏好的图表类型、单位、标题写法等）写进 instructions 或一个 Skill 即可，
  不需要写代码。
- 配色和文字颜色都是 CSS 变量（`--lv-chart-1` … `--lv-chart-8`、`--lv-chart-text`、
  `--lv-chart-title`、`--lv-chart-axis`、`--lv-chart-grid`），在[自定义模板](web-server.md#定制页面)
  的 `head` 块中覆盖即可匹配品牌风格。

## 表格

`show_table` 工具用交互式表格代替 Markdown 表格展示给用户：点击表头排序（再点一次倒序，第三次
恢复原顺序），行数较多时可以输入关键字筛选，每页 20 行翻页浏览。数字右对齐并按数值排序。
工具栏可以复制表格（制表符分隔，可直接粘贴到表格软件）、下载 CSV，或全屏查看；导出的都是当前
视图，也就是筛选、排序之后的结果。把聊天导出为 HTML 时，表格会以包含全部行的普通表格形式
包含在内。

`lovia web` 的默认 Agent 已带有这个工具；使用自己的 Agent 时，把工具加进去：`tools=[show_table]`
（从 `lovia.web` 导入）。更常用的做法
往往是让自己的工具返回 `ui_result("table", {"title": ..., "columns": [...], "rows": [[...], ...]})`：
行数据直接来自你的数据源（查询、API），模型不必逐个写出数字，更快、更省，也不会出错。单元格可以是
字符串、数字、布尔值或 null，按原样显示。表格不认识的键会被忽略，所以同一份 props 里还可以附带
给模型看的信息，比如总行数或生成这些数据的 SQL。结果很大时，可以用 `put_ui_data` 把行数据挡在
模型上下文之外：模型只看预览，表格仍显示全部行（见[大块数据](web-server.md#大块数据)）。

## 页面

`show_html` 工具可以在聊天中直接显示一个交互式页面：计算器、模拟、自定义可视化，凡是图表和表格
做不到的都可以。模型写出一个自包含的页面（CSS 和 JavaScript 都内联），卡片在沙箱中运行它。
`lovia web` 的默认 Agent 已带有这个工具；使用自己的 Agent 时，把工具加进去：`tools=[show_html]`
（从 `lovia.web` 导入）。你自己的工具也可以返回 `ui_result("html", {"html": page, "title": ...})`。

页面能做什么、不能做什么：

- 访问不到应用，也连不上网络。页面运行在不透明源中（没有 cookie、存储，也碰不到聊天内容），
  其安全策略拦下所有请求：没有 `fetch`、CDN 脚本、网络字体和远程图片。链接不会跳转。
- 可以通过 CSS 变量和聊天界面保持一致：`var(--lv-ink)`、`var(--lv-surface)`、`var(--lv-border)`、
  `var(--lv-accent)`、`var(--lv-chart-1)` … `var(--lv-chart-8)`，浅色和深色主题都适用。
- 按钮可以以用户身份追问：`lovia.send("按地区拆开看")`。只有在页面内真实点击时才会生效。
- 卡片随页面内容变高，最多占据大半个屏幕；支持全屏查看和下载 HTML。
- 重新打开聊天时，页面要点击 **运行** 才会启动，这样陷入死循环的页面不会在每次打开时卡住聊天。
  切换主题会重新加载页面。
- 导出的 HTML 不含脚本，因此只显示页面的源码。

## 不用重启的设置

助手的设置保存在 home 的 `config.json` 里，在设置页修改：开关和选项切换即保存，输入的文字有自己的
保存按钮。改动从下次运行起生效；正在进行的回复仍按开始时的设置完成。

| 设置页 | `config.json` | 默认值 |
| --- | --- | --- |
| **模型** → 模型的高级选项 | `models[].max_tokens` | Anthropic 格式为 16,384；OpenAI 兼容格式不发送，由服务端决定 |
| **助手** → 自定义指令 | `assistant.instructions` | 空：使用通用提示；填写后替换通用提示。两种情况下对话的[项目指令](#项目指令)都接在后面 |
| **助手** → 新对话的权限模式 | `assistant.mode` | `coding`，见[模式](workspace.md#模式)和[下文](#每个对话的权限模式) |
| **助手** → 不询问直接运行的命令（选“工作区内修改”时显示） | `assistant.auto_allow` | `read-only`、`dev-tools`：coding 模式免审批运行的[命令包](workspace.md#模式)（`ls`、`git status` 等；`pytest`、`ruff` 等）；清空则没有规则放行的命令一律询问 |
| **助手** → 网页搜索 | `assistant.search` | 开启；关闭后去掉 `web_search`（`web_fetch` 保留） |
| **助手** → 长期记忆 | `assistant.memory` | 开启，保存在 `<home>/memory` |
| **助手** → 后台子任务 | `assistant.subagents` | 开启 |
| **助手** → 生成追问建议 | `assistant.followups` | 开启 |
| **语音输入** | `voice`（`connection`，或 `base_url` 加 `api_key`；`model`；`language`） | 关闭，见[语音输入](#语音输入) |
| **通用** → 系统代理 | `trust_env` | 按启动时：经本机代理，绕过列表里的主机和本机地址直连；`LOVIA_HTTP_TRUST_ENV=0` 时直连。管所有自身设置（模型、MCP 服务器、联网搜索）为“跟随全局”的请求，包括 `web_fetch` |
| —（只在文件里，重启后生效） | `assistant.max_turns` / `assistant.max_retries` | `200` / `5` |

`config.json` 不可写时（比如只读挂载），服务照常启动，设置页里这些设置只能查看。

**通用**里的语言、回车键、通知和提示音，以及**外观**（主题、强调色、背景色调、正文字号与字体、对话宽度）
只属于当前浏览器，保存在它的本地存储里，不写入 `config.json`。

## 工作区

每个对话在自己的目录里工作。侧栏按目录给对话分组：启动 `lovia web` 的目录在最前，其余按最近的活动排序；**对话**
（`<home>/workspace`，给不属于任何项目的对话，图标是对话气泡而不是文件夹）始终在列表里。目录右侧的 **+** 在该目录新建对话；**⋯** 可以把它从列表移除——
文件和对话都会保留，重新添加该目录就能找回这些对话。**工作区**旁边的文件夹按钮用来添加目录，输入路径时会自动补全；它旁边的
显示方式按钮可以在“按工作区分组”和“按日期的单列表”之间切换，也可以在当前对话和已归档对话之间切换。拖动侧栏右边缘
可以调整宽度（双击还原）。

对话 **⋯** 菜单里的**归档**把对话收起来而不删除任何内容：它不再出现在列表里（搜索仍能找到），直到取消归档、置顶，
或再给它发一条消息。

新对话默认使用这个标签页上次用过的目录，输入框里的目录按钮会显示是哪个（悬停显示完整路径）；发送前可以在那里换一个。
对话的目录创建后不会再变，要在别处工作请新建对话。附件会保存到草稿所在的目录，所以草稿里有附件时目录按钮不能切换。
文件面板显示当前对话的目录，Agent 也会读取这个目录的 [`AGENTS.md`](#项目指令) 和 `.agents/skills`。

**另一台机器上的目录。**只要没有用 `--lock-workspace`（或 `--no-workspace`）启动，添加对话框里就有三个标签页：
**本机**、**SSH** 和**容器**。在后两个里填上主机（`~/.ssh/config` 里的别名，或 `user@host`；运行中的容器名，
想用默认用户以外的身份进入就写 `user@容器名`），列表里显示的就是**那台主机**上的目录。这个目录里的对话在那边运行：
Agent 的文件和命令工具都作用在主机上，受对话的权限模式约束，侧栏用服务器图标标出这个目录。主机需要有
`python3` 3.10 或更新版本，不用安装任何东西；SSH 必须能免密码登录（密钥或 agent）。文件面板显示的是主机上的这个目录，
发出的附件会复制一份到主机上、这个目录之外（见[图片与文件](#图片与文件)）；大文件的快慢取决于到主机的链路。
Agent 会按同样的规则读取主机上这个目录的 [`AGENTS.md`](#项目指令)（每次运行读一次）；目录里的技能目前还不加载，只有全局技能目录生效。连接断开时，进行中的运行会失败并说明原因，
下一条消息会重新连接。详见[远程工作区](workspace.md#远程工作区)。

早于工作区功能的旧对话归在 **未关联** 分组里。只是查看不需要做什么；第一次给它发消息时会先问它在哪个目录
（之前授权过的目录排在前面），分组上的 **关联…** 可以一次关联多个。关联后不能再更改。

用 `--lock-workspace` 启动时，所有对话都在启动目录里：没有目录可选，侧栏照旧按日期列出对话。

## 每个对话的权限模式

每个对话有自己的权限模式——**仅可查看**、**工作区内修改**或**完全权限**（`config.json` 和 API 里分别是 `readonly`、`coding`、`trusted`，见[模式](workspace.md#模式)），在输入框里目录按钮旁边切换。
新对话默认使用设置 → 助手里选的模式，发送前也可以先改。切换已有对话立即生效：正在进行的回复从下一次工具调用起按新模式判定，
对话的后台子任务一起切换，后台进程（比如开发服务器）不受影响。已经在等待的审批卡会按新模式重新判定：新模式允许的直接运行，
拒绝的带着原因被拒，仍需询问的继续等待。从"仅可查看"放宽时，正在进行的回复手里没有编辑文件和
运行命令的工具，要从下一条回复起才能用。运行中创建的对话——后台子任务、用 `start_session`
启动的对话、在这个对话里设置的定时任务新开的对话——沿用这次运行当前的模式。

按钮只提供服务端允许的模式（见下面的限制）。对话设置的模式服务端已不再提供时（比如重启时加了 `--readonly`），
按它下方最宽的可用模式运行，按钮上会注明；不会按更宽的模式运行。

## CLI 选项

命令行只保留服务自身的选项和部署方需要的工作区限制，按“命令行参数 → 环境变量 → 默认值”解析。

| 命令行选项 | 环境变量 | 默认值 |
| --- | --- | --- |
| `DIR`（位置参数） | `LOVIA_WORKSPACE` | `.`：新对话工作的目录；在主目录或根目录启动时改用通用工作区 `<home>/workspace` |
| `--home` | — | `~/.lovia`：配置、聊天记录、记忆和通用工作区 |
| `--readonly` | — | 关闭。开启后所有运行都是只读，设置页不能修改 |
| `--no-workspace` | — | 关闭。开启后没有文件和 shell 工具 |
| `--lock-workspace` | — | 关闭。开启后所有对话都在 `DIR` 里工作，浏览器不能打开其他目录，本机和远程都不行 |
| `--host` / `--port` | `LOVIA_HOST` / `LOVIA_PORT` | `127.0.0.1` / `8000` |
| `--root-path` | `LOVIA_ROOT_PATH` | 无；代理发布应用时使用的路径前缀（[详见](web-server.md#部署在路径前缀下)） |
| `--token` | `LOVIA_WEB_TOKEN` | 回环地址无需设置；其他地址自动生成 |
| `--db` | `LOVIA_DB` | `<home>/lovia.db` |
| `--app MODULE:ATTR` | `LOVIA_APP` | 创建默认 Agent（或使用自己的 Agent、映射或应用） |
| `--title` | `LOVIA_TITLE` | `lovia` |
| `--provider-timeout SECS` | `LOVIA_PROVIDER_TIMEOUT` | `300`；一次模型请求最长可用的时间 |
| — | `LOVIA_HTTP_TRUST_ENV` | 开启：出站请求（模型、MCP、网页读取）经 `HTTP(S)_PROXY` 或系统代理，遵守其绕过列表；设为 `0` 则直连。设置 → 通用 → 系统代理 优先于它（[详情](providers.md#网络超时代理tls)） |
| `--log-level` | `LOVIA_LOG_LEVEL` | `info` |
| `--check` | — | 检查模型配置并退出 |

绑定地址只决定要不要令牌：监听 `0.0.0.0` 的服务（比如在容器里）和监听 `127.0.0.1` 的一样，
所有模式、目录和远程工作区都可用；部署方用上面三个参数收紧。0.9.179 之前，监听非本机地址时
模式最高只到 `coding`、对话只能在 `DIR` 里，除非加 `--allow-workspace-switch`；这个参数已删除。

0.9.146 起移到设置页的选项（`--trusted`、`--auto-allow`、`--max-turns`、`--max-retries`、
`--max-tokens`、`--no-followups`、`--no-memory`、`--no-subagents`、
`--instructions`、`--instructions-file` 及对应的 `LOVIA_*` 环境变量）会让 CLI 报错退出，并说明
改到了哪个设置；`--memory-dir` 会指向 `--home`。自定义的 `--app` Agent 使用 CLI 默认值，要调整上限请在代码里用
`create_app(max_turns=…, retry=…, followups=…)`。完整列表以 `lovia web --help` 为准。

## 审批

[权限](tools.md#工具审批)判定为 `ask` 的 Tool 会让运行停在一张卡片上：卡片用 Tool 自己的名称
发问（“允许运行命令吗？”），有值得一提的*理由*时在下面补一行（“Pushes commits to a remote.”），
再原样显示模型发出的调用，然后是**允许**和**拒绝**——拒绝时可以附几行原因，模型会看到它并换做法，
而不是重试（⌘/Ctrl+Enter 直接带着原因拒绝）。卡片出现时会拿到键盘焦点，但焦点不在“允许”按钮上：
误按 Enter 不会批准任何东西。

判定给出了*范围*（`shell:git push`、`read:~/notes`）时，卡片还会提供**本对话中总是允许**，
放开的正是这些范围——像 `echo a; uname -a | head -1` 这样串起来的命令会列出要记住的每个命令
（`echo` `uname` `head`）；其中有一部分无法授权（`sudo`、shell 会展开的 `$VAR`）时就一个也不提供。
勾选框一次选中全部，点某个命令可单独取消（还没勾选时点它，就只选它这一个）——于是可以记住 `pwd`、
`uname` 而不带上 `python`。本次调用仍然整条运行，挑选只决定以后哪些调用不再询问。授权存在服务端，按对话记录，并绑定到给出时的 agent 和工作区根目录：之后被完全覆盖
的调用在任何人看到之前就已批准，不出卡片；对话换到别的工作区时不会沿用。授权永远不作用于
`deny`，新对话不会继承。对话的后台子任务与对话共用授权：在子任务里点的“总是允许”记在对话上，
对话里记住的也覆盖它的子任务。

卡片只在等待决定时出现。一旦有了结论——你、另一个标签页、超时还是停止——卡片消失，结果以标签的形式
留在这次调用自己的工具行上：**已允许**（悬停可见记住了哪些）、**已拒绝**（悬停可见拒绝原因）、
**已停止**；被授权自动放行的调用标为**自动允许**，点它可以查看这个对话的授权并撤销
（撤销只影响之后的调用）。被拒绝的调用当场补上工具行，随后由它的报错结果填充，和刷新后看到的一致。

在 `lovia web` 里，审批一分钟无人回答时，运行会暂停：停在这个调用上并释放槽位，卡片保留，标着
**已暂停 · 批准后继续**。之后随时回答都可以——刷新后、服务重启后也行——运行从这个调用接着跑；
往对话里发消息也会让它续跑（卡片会再问一次，回答之后才读到这条消息）。侧栏会标出这样等待中的对话，
发往它的定时任务会跳过，期间送达的子任务报告会随运行一起等待。这样定时任务和后台任务不会长期占用
运行槽位，也不会因为没人回答而被拒绝。自己的应用用 `create_app(suspend_after=...)` 设置等待时长
（`None` 表示一直在线等待回答）。

运行在等你的时候——你没在看的对话里出现了审批卡片或问题，或者运行因此暂停——会像运行完成时一样提醒你一次：
弹出带**打开**按钮的提示；标签页在后台时，标题上的计数加一，在设置里开启了桌面通知的话还会发一条通知，
点它就打开那个对话。

## 来自 Agent 的提问

默认 Agent 带有 [`ask_human`](built-in-tools.md#询问人工) Tool。等待中的问题保存在服务端，
所以刷新或重新连接不会丢失。和审批卡片一样，问题一分钟无人回答时运行会暂停（释放槽位，卡片保留）：
之后随时回答都可以——刷新后、服务重启后也行——运行带着你的回答接着跑。这样定时任务和后台任务
不会长期占用运行槽位。

自定义 Agent 需要把同一个 `HumanChannel` 同时交给 Tool 和 Web 应用：

```python
from lovia import Agent
from lovia.tools import HumanChannel, ask_human
from lovia.web import create_app, serve

channel = HumanChannel()
agent = Agent(name="bot", model="<model>", tools=[ask_human(channel)])
serve(create_app(agent, question_channel=channel, suspend_after=60))
```

## 追问建议

追问建议来自一次独立模型调用，不会写入 Transcript。关闭它可以避免这次额外调用：在**设置 →
助手**里关闭，也可以把辅助任务角色指派给更便宜的模型（见[模型配置与切换](#模型配置与切换)）。
通过 `create_app()` 托管自定义 Agent 时，该功能默认关闭，需要显式开启，见
[Web 服务端](web-server.md#追问建议)。

## 语音输入

用说的代替打字。默认关闭：在**设置 → 语音输入**里选好转写服务之后，输入框里才会出现麦克风。

| 操作 | 结果 |
| --- | --- |
| 点麦克风，或按 Ctrl+M | 开始录音；再按一次 Ctrl+M 结束 |
| 按住麦克风或 Ctrl+M | 说话，松开即结束 |
| ✓，或发送键 | 转写后把文字放到光标处，先检查 |
| ↑ | 转写后直接发送 |
| ✕，或 Esc | 取消；5 秒内可以点**恢复**找回这段录音 |

录音期间，输入框自己的发送键等于 ✓，不会发送：放进输入框的文字可以撤销，发出去的消息收不回。
录音时输入框照常可以打字，运行中的停止键也始终在原位。

一段录音最长五分钟（服务自己的上限更短时以它为准，如 DeepSeek 的两分钟），结束后整段转写。切到别的对话会结束录音，文字加进原来那个对话的草稿。
麦克风中途断开时，已经录到的部分照常转写。

设置里的**连接**可以沿用某个已配置模型的地址和密钥（只列出 OpenAI 兼容的），也可以单独填
接口地址和密钥。接口地址填 API 根地址（`https://api.openai.com/v1`）或完整的转写接口地址
（`https://api.deepseek.com/v1/tools/asr`）都可以：没有路径、或路径以版本号或 `/openai` 结尾的当作根地址，
其余原样使用。然后填转写模型，例如 `gpt-transcribe`、`whisper-large-v3-turbo`；一句话里
混着说几种语言时，再选主要的语言。DeepSeek 最省事：沿用它的聊天连接即可，模型留空。**试录一句**会把麦克风、密钥、模型和语言一起验证一遍。

需要知道的：

- 录音会发送到你选的服务，可能产生费用。lovia 不保存录音：不落盘，也不进对话。
- 浏览器只允许 HTTPS 或 `localhost` 页面使用麦克风。局域网的 HTTP 地址上，点按钮时会说明原因。
- 经过反向代理时，长录音需要更大的请求体上限，见[部署](deployment.md)。
- 没发出去的录音在刷新后会丢失；离开页面前会有提示。

语音输入仍是实验性功能：它背后的 HTTP 路由和 Python 名字还可能调整（见
[Web 服务端](web-server.md#语音输入)）。

## 运行与连接的边界

Run 由服务端托管，刷新或关闭页面不会取消它；重新连接后会从服务端状态继续。显式停止 Run 时，
已经完成的 Turn 仍保留在 Session 中。

服务优雅关闭时会保留主 Run 的 Checkpoint，重启后可以恢复；审批和 SSE 订阅等进程内状态不会恢复。
Shell 后台进程和后台子 Agent 也不会随 Checkpoint 恢复。

因轮数上限、预算，或模型、网络故障而停下的 Run 仍是这个对话的 Run：对话里会说明它为什么停下，
你发的下一条消息（"继续"或别的任何话）会让它从停下的地方接着运行，原来的计划和已完成的工作都在，
各项上限从此处重新计算。只是打开对话不会让它自己重新开始。

Run 执行期间发送的消息有两种处理方式，按条决定：

- **排队**（Enter）：消息显示在输入框上方，等当前 Run **成功完成**后作为单独的 Run 发送。多条排队消息逐条发送，
  每条都等上一条的 Run 完成。Run 失败或被停止时队列会暂停，可以点「立即发送」或撤回消息继续。
  排队消息只保存在当前浏览器标签页中：仅在该对话打开时发送，刷新页面后会丢失。
- **插话**（⌥/Alt+Enter，或排队消息上的「插话」）：作为当前 Run 下一 Turn 的追加指令；如果当前 Run
  恰好结束，用 ⌥/Alt+Enter 发出的会按顺序进入新的 Run，从队列插话的则回到队首，照常排队。
  插话没有收到应答（例如网络中断）时，它可能已经送达，所以不会自动重发：它停在队首并暂停，等你核对对话。

Run 执行期间也可以添加附件，它们随消息一起发送，无论排队还是插话。有附件还在上传时，「发送」会等上传完成。
排队消息还可以放回输入框编辑（输入框和附件栏都为空时，文字和附件一起放回），或者撤回。

## 定时任务

侧栏的**定时任务**打开任务页面（`?view=lovia-schedules`），分为已启用、已暂停和已结束（默认折叠）
三组。每行显示名称、下次运行时间、上次结果和暂停开关。点开一个任务，可以看到它的指令、设置和运行历史：
每次运行都链接到对应的对话；因上一次运行还没结束而跳过的触发也会列出，并写明原因。

**新建任务**（或空页面上的示例）打开表单：名称、指令和频率。频率可以选**一次**、**按天**（选星期和时间）、
**间隔**，或直接写 **Cron** 表达式；保存前会显示接下来三次的运行时间。对话能选文件夹和权限模式的地方，
定时任务也能选。任务运行时无人值守，需要批准的操作会在审批超时后被拒绝。停止条件和上限收在折叠区里。
Cron 按服务器时钟计算；浏览器时区不同时，表单会提示。

也可以在对话里直接说"每个工作日 9 点帮我汇总……"，批准 `schedule_run` 调用即可。之后每次运行都续写这个对话
（除非你要求每次新开对话），它的顶栏会显示这些定时任务。由定时任务新建的对话，
在侧栏带一个时钟标记，顶栏可以跳回对应的任务。

## 分支对话

每条已完成的回复上都有 **在新对话中分支**：它新建一个对话，包含到这条回复为止的全部内容，
你可以从这里把对话引向另一个方向。从最后一条回复分支，就是复制整个对话。某条回复之后若有
仍在运行的 Run，这条回复要等该 Run 结束后才会出现分支按钮。分支复制的是服务端当时保存的
内容。原对话不受影响，新对话会链接回原对话，删除其中一个不影响另一个。

分支复制的是对话，不是工作区：分支点之后写入的文件保持当前状态。

让 agent “在新对话里”做某件事时，它可以自己新建对话（`start_session`）。点击工具卡片即可打开
新对话；新对话不带当前对话的任何内容，并会链接回发起它的对话。

助手也能回答关于应用本身的问题：你有哪些工作区、之前某个对话定下了什么、本对话用的是哪个
模型或模式。它会用只读工具去查（[自省](web-server.md#自省)）。

## 后台子 Agent

`lovia web` 默认启用[后台子 Agent](multi-agent.md#后台子-agent)，可在**设置 → 助手**里关闭。
默认子 Agent 保留 Skills、Todo、Tool 和 Workspace，但不加载 Scheduling、Introspection、Memory 或 Subagents，
因此不会递归派生。

自定义 Agent 需要自行添加 `Subagents` Plugin。`create_app()` 会把使用默认执行方式的 Plugin
接入 Web 托管；可用 `create_app(..., wire_subagents=False)` 禁用。直接挂载
`build_api_router` 时，需要调用一次 `wire_subagents(deps)`。

每个后台任务都有独立 Session。任务完成后，报告会送回父对话：父 Run 仍在执行时进入下一 Turn；
父对话空闲时，服务端会自动启动一次 Run 处理报告。浏览器无需保持在线。但如果父对话最近一次 Run
是被停止的，报告只会留在对话里，不再自动启动 Run——你说了停，下一条消息时模型会连同报告一起读到。
报告在对话里显示为一张可折叠的卡片，不算作你发的消息：↑/↓ 翻历史时会跳过它，也没有编辑按钮。

后台任务不属于父 Run，因此停止父 Run 不会停止它——停止后会提示还有几个任务在运行，并提供「一并停止」；删除父对话则会停止它的后台任务，并一并删除。后台任务的审批和其他运行一样会暂停：派生它的对话继续等它，在任务对话或父对话的托盘里回答卡片后，任务接着跑完。服务关闭时后台任务会被停止而不是暂停；
服务重启后，尚未完成的后台任务不会恢复。

后台任务的审批卡片也会出现在派生它的对话里，位于输入框上方，标着任务名并带“打开任务”链接；在任一处回答，
两处同时结束。后台任务按对话的权限模式运行，并与对话共用“总是允许”的授权。
