# Web UI

Web UI 是 lovia 自带的本地聊天应用，适合直接使用 Agent，或在开发自定义前端前验证功能。

## 一条命令启动

```bash
pip install "lovia[web]"
lovia web
```

访问 `http://127.0.0.1:8000`，首次启动时配置一个模型即可。之后可用
`lovia web --check` 检查配置并探测端点，而不启动服务。

服务保存的一切都在一个目录里，即 lovia 的 **home**——默认 `~/.lovia`，`--home DIR`
可以换成别处。启动目录里的东西一概不读，它只决定新对话默认在哪个目录工作：

| home 里的 | 内容 |
| --- | --- |
| `config.json` | 模型、Web 搜索、全局技能目录，以及各个 [Agent](#agent) |
| `lovia.db` | 聊天记录（`--db FILE` 可放到别处） |
| `memory/` | 长期记忆：关于你的笔记，`scopes/` 下按项目分开的笔记和历史 |
| `workspace/` | 不属于任何项目的对话的工作区 |

互不相干的环境——一个测试实例、不同的客户——各用一个 `--home`。在支持 Unix 权限的平台上，
home 只允许当前用户访问，里面还放了一个内容为 `*` 的 `.gitignore`，所以放在仓库里的 home
不会被提交。home 必须是 lovia 专用的目录：仓库根目录，或者 `.gitignore` 没有忽略全部内容的目录，
会在写入任何东西之前被拒绝。

0.9.179 之前，启动目录里的 `./.lovia/config.json` 会整体取代用户的配置，那里已有的
`./.lovia/lovia.db` 会被沿用，记忆默认放在 `./.lovia/memory`。这些现在都不再读取；
`lovia web --home ./.lovia` 与以前在那个目录启动的行为完全一样。没有传 `--home` 而启动目录里有
`./.lovia/config.json` 时，服务会打一行日志说明这一点。

CLI 创建的默认 Agent 包含 Todo、Memory、时间与 HTTP Tool、Web 搜索、定时任务，以及以
当前目录为根的 coding 模式 Workspace。它每次运行都从对话所在的目录读取：

- `AGENTS.md`：作为 Agent instructions；
- `.agents/skills`：项目自己的技能，排在全局技能目录（默认 `~/.agents/skills`，在设置 → 技能中管理）之前。

所以在另一个项目里的对话会遵循那个项目的 `AGENTS.md` 和技能。Web 搜索在配置 Tavily Key 后
使用 Tavily，否则尝试可选的 DuckDuckGo 后端。

默认功能会产生主 Run 之外的模型调用：Memory 默认在每个已完成 Run 后提炼一次，定期整理时
再调用一次；标题和追问建议也各自独立调用。可以在**设置 → Agent** 里给某个 Agent 关闭长期记忆或追问建议，
或把辅助任务指派给更便宜的模型。Memory 的完整成本边界见[记忆](memory.md#使用建议)。

!!! danger "默认仅供本机使用"

    回环地址 `127.0.0.1` 默认不鉴权。绑定其他地址时必须设置 `--token` 或
    `LOVIA_WEB_TOKEN`；未设置时服务会自动生成。持有 token 的客户端可以使用 Agent 的
    全部能力，包括编辑文件、执行 Shell 命令、打开其他目录和远程工作区——除此之外绑定地址不改变
    任何行为，因此应把 token 当作密码。允许其他设备访问时，用 `--readonly`、`--lock-workspace`
    或 `--no-workspace` 收紧；多用户部署请参阅[生产部署](deployment.md)。

## 模型配置与切换

模型档案保存在 `config.json` 中，在**设置 → 连接**里编辑，Web 搜索服务也在这一页。连接测试会真实检查端点可达性、认证、模型列表和上下文窗口；
端点未列出的模型 ID 仍可手动填写。

API Key 只写不读：服务端只返回是否已设置及脱敏提示，不会把完整密钥传回浏览器。配置更新会
整体校验、原子写入并立即生效，无需重启。

切换模型从**下一条消息**开始生效，包括旧对话的后续消息、定时任务和后台子 Agent；已经开始的
回复仍使用原模型。输入框里的模型按钮切换的是这个对话的 [Agent](#agent) 所用的模型：Agent 指定了模型就换它的，
否则换默认模型，所有没指定模型的 Agent 都跟着换。视觉理解以及标题、追问建议等辅助任务，可以分别指派给其他模型档案。

**额外请求参数**（高级）是一个 JSON 对象，原样合并进发给该端点的每个请求——即 provider 的
[`extra_body`](providers.md#extra_body连接级的请求字段)。推理相关的配置就靠它，按端点自己的
写法填，因为一个 OpenAI 兼容格式背后藏着许多方言：OpenAI、DeepSeek、Qwen 3.8 和 vLLM 用
`{"reasoning_effort": "medium"}`；vLLM/SGLang 部署的 Qwen、GLM 用
`{"chat_template_kwargs": {"enable_thinking": false}}`；DeepSeek 与智谱官方 API 用
`{"thinking": {"type": "disabled"}}`；Anthropic 用 `{"output_config": {"effort": "medium"}}`。
值为 `null` 表示删除适配器本来会发的字段（拒绝 `stream_options` 的网关可写
`{"stream_options": null}`）。不做任何转换，端点接受什么由端点决定——官方 API 会在下一条消息
时拒绝不认识的字段，vLLM 则可能静默忽略；对话里有没有思考痕迹才是真正的检验。编辑框下方的
快捷片段只负责写入这些形状，不代表模型支持。

经过这个档案的每一次调用都会带上这些字段——主回复、后台子 Agent、上下文压缩摘要，以及被指派为
视觉或辅助角色时的图片描述、标题和追问。同一端点想要第二套参数，就是第二个档案：**复制**在服务端
完成（连密钥一起，因为页面从不持有它），所以"标题不思考"就是复制一份、写上
`enable_thinking: false`、指派给辅助角色。思考模型需要输出空间：可以在档案的高级选项里设置
**最大输出 tokens**（额外字段里的 `max_tokens` 优先于它）。它限制用这个档案的对话回复和后台子 Agent，
不限制标题、追问建议和图片描述；上下文策略的输出预留也不会跟着变。

搜索后端、Tavily Key 与 Skill 目录也保存在 `config.json` 中。模型连接、多模型档案、
角色指派、搜索和 Skills 配置没有对应的 CLI 参数；请通过设置页或直接维护配置文件。

## Skills

技能从两处加载；每个 skill 是含 `SKILL.md` 的子目录（详见 [Skills](skills.md)）：

- **项目自己的** `.agents/skills`，位于对话所在目录的根下。它和 `AGENTS.md` 一样是约定，
  不是配置项：在该项目的每个对话里自动加载，重名时优先。远程工作区里的对话暂时拿不到项目的技能。
- **全局目录**，在设置 → 技能中管理——一个有序列表，只接受绝对路径或 `~` 开头的路径，
  对所有对话都一样；重名时靠前的目录优先。默认是 `~/.agents/skills`；移除它即禁用，
  也可以添加任意其他目录。相对路径会被拒绝，因为它在每个对话里指向不同的目录
  （已保存文件里旧的 `.agents/skills` 条目会被丢掉：它本来就会加载）。

面板只列全局目录，并展示每个目录的贡献——发现的 skills、解析问题、被遮蔽的重名项；
不存在的目录会被直接跳过，过期条目不会阻止服务启动。列表变更立即生效；向已配置的目录里
新增 skill 则无需任何操作。某个 Agent 也可以改用自己的一组目录（见下文）；项目自己的技能照常加载。

## Agent

`lovia web` 起初只有一个 Agent `lovia`，在**设置 → Agent** 里可以再建。每个 Agent 是一种工作方式：有自己的名称和说明、
提示词、模型、权限模式和免确认命令、技能目录、开关（网页搜索、长期记忆、后台子任务、追问建议）和运行上限。
连接——模型、密钥、搜索服务——在设置 → 连接里配一次，各个 Agent 共用，Agent 只是引用它们。

- 新对话在输入框下方选 Agent（目录、权限模式两个按钮旁边，多于一个 Agent 时才显示）。默认是这个目录最近一个对话用的
  Agent，没有就用默认 Agent——列表第一个（**设为默认**会把它挪到第一位）；权限模式取这个 Agent 的设置。
- 对话一直用创建时的 Agent，按钮只显示、不能换。对话的 Agent 被删除后，它由默认 Agent 继续，打开时页面会提示。
  定时任务的 Agent 被删除后，任务会失败并说明是哪个 Agent，直到改用别的 Agent。
- 对话和定时任务存的是 Agent 的 `id`。它在新建时由名称生成，之后不变，所以改名不影响已有对话。
- 长期记忆所有开启记忆的 Agent 共用，按项目分层（见[记忆的作用域](memory.md#作用域)）：关于你的笔记只有一份，
  每个项目的对话都带上；关于项目的笔记和历史对话检索按对话所在的目录分开，"无项目"的对话只有前一层。
  侧栏底部的**记忆**对话框有两个标签："关于我"和"本项目（项目名）"，后者只在属于某个项目的对话里出现，
  里面的**清空本项目记忆**会删掉这个项目的笔记和历史对话检索，不可撤销；删对话不会顺带清记忆。
  按目录识别项目，目录改名或移动后项目记忆就断开了。更早版本存下的笔记都留在"关于我"，里面关于某个项目的条目可以手工挪到"本项目"。

`config.json` 里没写的字段取默认值（见[下文](#不用重启的设置)）：

```json
{
  "version": 2,
  "agents": [
    {"id": "lovia"},
    {"id": "review", "name": "代码审查", "description": "只读代码，不改文件",
     "instructions": "审查改动，不要编辑文件。",
     "mode": "readonly", "model": "fast"}
  ]
}
```

!!! note "从 0.9.179 及更早版本升级"

    `config.json` 第 1 版把唯一那个 Agent 的设置放在 `agent`、`run`、`workspace` 三段里。这三段不会折算：
    默认 Agent 从默认值开始（提示词、权限模式、免确认命令、开关和上限），下次保存时写成第 2 版。
    模型、角色、搜索和技能照常保留。

## 加载自定义 Agent

创建 `app.py`：

```python
from lovia import Agent

assistant = Agent(
    name="assistant",
    instructions="清晰回答，并在有助于提高准确性时使用工具。",
    model="<model>",
)
```

然后运行：

```bash
lovia web --app app:assistant
```

`--app MODULE:ATTR` 接受一个 Agent、`{name: agent}` 映射，或由 `create_app()` 构建的应用
（也可以是返回其中任意一种的无参工厂函数）。应用会按构建时的配置原样运行，沿用自定义的认证、
存储和 UI 选项；CLI 仍负责 host、port、日志和启动信息。原本会传给 `create_app()` 的选项
（`--token`、`--db`、`--title` 等）会被忽略并给出警告。Python 部署和 ASGI 集成详见
[Web 服务端](web-server.md)。

界面支持 GitHub 风格 Markdown、代码高亮、Mermaid 和内嵌图片。默认 Agent 已知道这些能力；
自定义 Agent 不会自动获得相关提示。如果希望模型主动使用这些格式，可以加入 `SURFACE_NOTE`：

```python
from lovia.web import SURFACE_NOTE

assistant = Agent(
    name="assistant",
    instructions="清晰回答。\n\n" + SURFACE_NOTE,
    model="<model>",
)
```

## 图片与文件

附件会写入 Workspace 的 `uploads/`，消息中保存的是相对路径。因此，即使模型不能直接读取附件，
Agent 仍可通过 Workspace Tool 打开文件。`--no-workspace` 会同时关闭这条路径。

Markdown 图片可以直接引用 Workspace 内的文件——`![chart](uploads/chart.png)` 会显示该文件本身，
回复和文件面板的 Markdown 预览都是如此。路径先按文档自身所在目录解析，再按 Workspace 根目录解析；
读取走的是与预览相同的只读接口。SVG 也能显示，走的是该接口的附件形式：浏览器对图片子资源会忽略
`Content-Disposition`（此时 SVG 里的脚本被禁用），对导航则会遵守（此时脚本本会执行）——于是图能显示，
而 URL 本身只会下载。

链接（`[report](report.md)`）指向同一个接口：在回复中，浏览器能直接显示的文件（图片、PDF）会在
新标签页打开，其余文件直接下载，对话本身不会被导航掉；在文件面板内，同样的链接则在查看器中打开。
回复里的外部链接同样在新标签页打开。

图片是否内联发送由视觉配置决定：

- 官方 OpenAI 和 Anthropic 端点默认按支持视觉处理；其他视觉端点需要把该模型配置的视觉能力
  设为“支持”（即 `config.json` 中的 `"vision": "on"`）。
- 纯文本主模型可以把视觉角色指派给另一个模型配置。此时主模型通过 `describe_image` Tool
  获得文字结果，图片原始数据不会写入主模型的对话历史。

单个文件默认不超过 25 MiB，可用 `LOVIA_MAX_UPLOAD_MB` 调整。带扩展名的文件受内置白名单限制；
`LOVIA_UPLOAD_ALLOWED_EXT` 可覆盖白名单，使用逗号或空格分隔，`*` 表示不限。

通过文件面板上传的文件不会自动附加到下一条消息。"最近"列表不列环境噪音（`node_modules/`、
`venv/`、`__pycache__/`、`*.pyc`）和 Agent 的临时目录 `tmp/`，"新文件"角标也只统计会出现在
"最近"里的写入——这只是展示规则：目录浏览显示所有目录，Agent 引用的任何路径（回复里 `tmp/`
下的图片、工具卡片的"在文件面板打开"）只要 Agent 自己能读就能打开。删除聊天也不会删除
`uploads/` 中的文件，需要由应用或用户清理。

后台进程属于聊天而不是单次 Run：Run 结束不会终止它们；删除聊天或停止 Web 服务时会统一清理，
服务重启后也不会恢复。更完整的生命周期见[工作区](workspace.md#后台进程)。

## 图表

`show_chart` 工具可以在聊天中绘制交互式图表，支持折线、柱状、饼图、散点、热力图、K 线、
桑基图等 [Apache ECharts](https://echarts.apache.org/) 的系列类型。模型把 ECharts option
写成调用参数，卡片负责渲染；实时对话和重新打开会话时都会显示。`lovia web` 的默认 Agent
已带有这个工具；使用自己的 Agent 时，把工具加进去：`tools=[show_chart]`（从 `lovia.web` 导入）。任何工具也都
可以产出图表：`return ui_result("chart", option)`，直接用真实数据作图，不需要模型抄写数字
（见[UI 组件](web-server.md#ui-组件)）。如果工具的 option 来自模型（比如执行查询后把结果行放进
option 的 `dataset`），先用 `validate_chart_option(option)` 检查：它抛出与 `show_chart` 相同的
工具错误，模型可以据此修正 option 后重试。

图表标题显示为卡片标题，位于图表上方，不会与图例重叠。标题旁的工具栏（鼠标悬停时显示）可以
把图表下载为 PNG 或 SVG（包含标题）、把数据下载为 CSV（树图、桑基图、关系图没有表格结构，
下载为 JSON），也可以全屏查看。

须知：

- ECharts（约 1 MB，已随包内置）在出现第一张图时才加载，没有图表的会话不会请求它。
- 把聊天导出为 HTML 时，每张图表以 SVG 图片的形式包含在内。
- option 在绘制前会经过过滤：图片、链接、`graphic` 和 `toolbox` 组件、HTML 形式的
  tooltip 都会被去掉；需要代码或地图数据的系列类型（`custom`、`map`）也不支持。
- 团队的作图约定（偏好的图表类型、单位、标题写法等）写进 instructions 或一个 Skill 即可，
  不需要写代码。
- 配色和文字颜色都是 CSS 变量（`--lv-chart-1` … `--lv-chart-8`、`--lv-chart-text`、
  `--lv-chart-title`、`--lv-chart-axis`、`--lv-chart-grid`），在[自定义模板](web-server.md#定制页面)
  的 `head` 块中覆盖即可匹配品牌风格。

## 表格

`show_table` 工具用交互式表格代替 Markdown 表格展示给用户：点击表头排序（再点一次倒序，第三次
恢复原顺序），行数较多时可以输入关键字筛选，每页 20 行翻页浏览。数字右对齐并按数值排序。
工具栏可以复制表格（制表符分隔，可直接粘贴到表格软件）、下载 CSV，或全屏查看；导出的都是当前
视图，也就是筛选、排序之后的结果。把聊天导出为 HTML 时，表格会以包含全部行的普通表格形式
包含在内。

`lovia web` 的默认 Agent 已带有这个工具；使用自己的 Agent 时，把工具加进去：`tools=[show_table]`
（从 `lovia.web` 导入）。更常用的做法
往往是让自己的工具返回 `ui_result("table", {"title": ..., "columns": [...], "rows": [[...], ...]})`：
行数据直接来自你的数据源（查询、API），模型不必逐个写出数字，更快、更省，也不会出错。单元格可以是
字符串、数字、布尔值或 null，按原样显示。表格不认识的键会被忽略，所以同一份 props 里还可以附带
给模型看的信息，比如总行数或生成这些数据的 SQL。结果很大时，可以用 `put_ui_data` 把行数据挡在
模型上下文之外：模型只看预览，表格仍显示全部行（见[大块数据](web-server.md#大块数据)）。

## 页面

`show_html` 工具可以在聊天中直接显示一个交互式页面：计算器、模拟、自定义可视化，凡是图表和表格
做不到的都可以。模型写出一个自包含的页面（CSS 和 JavaScript 都内联），卡片在沙箱中运行它。
`lovia web` 的默认 Agent 已带有这个工具；使用自己的 Agent 时，把工具加进去：`tools=[show_html]`
（从 `lovia.web` 导入）。你自己的工具也可以返回 `ui_result("html", {"html": page, "title": ...})`。

页面能做什么、不能做什么：

- 访问不到应用，也连不上网络。页面运行在不透明源中（没有 cookie、存储，也碰不到聊天内容），
  其安全策略拦下所有请求：没有 `fetch`、CDN 脚本、网络字体和远程图片。链接不会跳转。
- 可以通过 CSS 变量和聊天界面保持一致：`var(--lv-ink)`、`var(--lv-surface)`、`var(--lv-border)`、
  `var(--lv-accent)`、`var(--lv-chart-1)` … `var(--lv-chart-8)`，浅色和深色主题都适用。
- 按钮可以以用户身份追问：`lovia.send("按地区拆开看")`。只有在页面内真实点击时才会生效。
- 卡片随页面内容变高，最多占据大半个屏幕；支持全屏查看和下载 HTML。
- 重新打开聊天时，页面要点击 **运行** 才会启动，这样陷入死循环的页面不会在每次打开时卡住聊天。
  切换主题会重新加载页面。
- 导出的 HTML 不含脚本，因此只显示页面的源码。

## 不用重启的设置

各个 Agent 的设置都保存在 home 的 `config.json` 里，在设置页修改。保存后从下次运行起生效；正在进行的
回复仍按开始时的设置完成。

| 设置页 | `config.json` | 默认值 |
| --- | --- | --- |
| **连接** → 模型的高级选项 | `models[].max_tokens` | 沿用 Provider 的默认值 |
| **Agent** → 模型 | `agents[].model` | `null`：默认聊天模型 |
| **Agent** → 自定义指令 | `agents[].instructions` | 空：使用对话所在目录的 `AGENTS.md`，没有就用通用提示；填写后 `AGENTS.md` 接在后面 |
| **Agent** → 新对话的权限模式 | `agents[].mode` | `coding`，见[模式](workspace.md#模式)和[下文](#每个对话的权限模式) |
| **Agent** → 不询问直接运行的命令（选“工作区内修改”时显示） | `agents[].auto_allow` | `read-only`、`dev-tools`：coding 模式免审批运行的[命令包](workspace.md#模式)（`ls`、`git status` 等；`pytest`、`ruff` 等）；清空则没有规则放行的命令一律询问 |
| **Agent** → 技能 | `agents[].skills` | `null`：全局技能目录；填列表则改用这些目录 |
| **Agent** → 网页搜索 | `agents[].search` | 开启；关闭后去掉 `web_search`（`web_fetch` 保留） |
| **Agent** → 长期记忆 | `agents[].memory` | 开启，保存在 `<home>/memory` |
| **Agent** → 后台子任务 | `agents[].subagents` | 开启 |
| **Agent** → 生成追问建议 | `agents[].followups` | 开启 |
| **Agent** → 最大轮数 / 重试次数 | `agents[].max_turns` / `agents[].max_retries` | `100` / core 的默认值（`4`） |

`config.json` 不可写时（比如只读挂载），服务照常启动，设置页里这些设置只能查看。

## 工作区

每个对话在自己的目录里工作。侧栏按目录给对话分组：启动 `lovia web` 的目录在最前，其余按最近的活动排序；**无项目**
（`<home>/workspace`，给不属于任何项目的对话）始终在列表里。目录右侧的 **+** 在该目录新建对话；**⋯** 可以把它从列表移除——
文件和对话都会保留，重新添加该目录就能找回这些对话。**对话**旁边的文件夹按钮用来添加目录，输入路径时会自动补全；它旁边的
显示方式按钮可以在“按工作区分组”和“按日期的单列表”之间切换，也可以在当前对话和已归档对话之间切换。拖动侧栏右边缘
可以调整宽度（双击还原）。

对话 **⋯** 菜单里的**归档**把对话收起来而不删除任何内容：它不再出现在列表里（搜索仍能找到），直到取消归档、置顶，
或再给它发一条消息。

新对话默认使用这个标签页上次用过的目录，输入框里的目录按钮会显示是哪个（悬停显示完整路径）；发送前可以在那里换一个。
对话的目录创建后不会再变，要在别处工作请新建对话。附件会保存到草稿所在的目录，所以草稿里有附件时目录按钮不能切换。
文件面板显示当前对话的目录，Agent 也会读取这个目录的 `AGENTS.md` 和 `.agents/skills`。

**另一台机器上的目录。**只要没有用 `--lock-workspace`（或 `--no-workspace`）启动，添加对话框里就有三个标签页：
**本机**、**SSH** 和**容器**。在后两个里填上主机（`~/.ssh/config` 里的别名，或 `user@host`；运行中的容器名，
想用默认用户以外的身份进入就写 `user@容器名`），列表里显示的就是**那台主机**上的目录。这个目录里的对话在那边运行：
Agent 的文件和命令工具都作用在主机上，受对话的权限模式约束，侧栏用服务器图标标出这个目录。主机需要有
`python3` 3.10 或更新版本，不用安装任何东西；SSH 必须能免密码登录（密钥或 agent）。文件面板显示的是主机上的这个目录，
上传的文件和附件也保存在那里（和本机目录一样放在 `uploads/` 下）；大文件的快慢取决于到主机的链路。
Agent 会读取主机上这个目录的 `AGENTS.md`（每次运行读一次）；目录里的技能目前还不加载，只有全局技能目录生效。连接断开时，进行中的运行会失败并说明原因，
下一条消息会重新连接。详见[远程工作区](workspace.md#远程工作区)。

早于工作区功能的旧对话归在 **未关联** 分组里。只是查看不需要做什么；第一次给它发消息时会先问它在哪个目录
（之前授权过的目录排在前面），分组上的 **关联…** 可以一次关联多个。关联后不能再更改。

用 `--lock-workspace` 启动时，所有对话都在启动目录里：没有目录可选，侧栏照旧按日期列出对话。

## 每个对话的权限模式

每个对话有自己的权限模式——**仅可查看**、**工作区内修改**或**完全权限**（`config.json` 和 API 里分别是 `readonly`、`coding`、`trusted`，见[模式](workspace.md#模式)），在输入框里目录按钮旁边切换。
新对话默认使用所选 Agent 的模式，发送前也可以先改。切换已有对话从下次运行起生效：正在进行的回复仍按开始时的
模式完成，对话的后台进程（比如开发服务器）也不受影响。运行中创建的对话——后台子任务、用 `start_session`
启动的对话、在这个对话里设置的定时任务新开的对话——沿用这次运行的模式。

按钮只提供服务端允许的模式（见下面的限制）。对话设置的模式服务端已不再提供时（比如重启时加了 `--readonly`），
按它下方最宽的可用模式运行，按钮上会注明；不会按更宽的模式运行。

## CLI 选项

命令行只保留服务自身的选项和部署方需要的工作区限制，按“命令行参数 → 环境变量 → 默认值”解析。

| 命令行选项 | 环境变量 | 默认值 |
| --- | --- | --- |
| `DIR`（位置参数） | `LOVIA_WORKSPACE` | `.`：新对话工作的目录；在主目录或根目录启动时改用通用工作区 `<home>/workspace` |
| `--home` | — | `~/.lovia`：配置、聊天记录、记忆和通用工作区 |
| `--readonly` | — | 关闭。开启后所有运行都是只读，设置页不能修改 |
| `--no-workspace` | — | 关闭。开启后没有文件和 shell 工具 |
| `--lock-workspace` | — | 关闭。开启后所有对话都在 `DIR` 里工作，浏览器不能打开其他目录，本机和远程都不行 |
| `--host` / `--port` | `LOVIA_HOST` / `LOVIA_PORT` | `127.0.0.1` / `8000` |
| `--root-path` | `LOVIA_ROOT_PATH` | 无；代理发布应用时使用的路径前缀（[详见](web-server.md#部署在路径前缀下)） |
| `--token` | `LOVIA_WEB_TOKEN` | 回环地址无需设置；其他地址自动生成 |
| `--db` | `LOVIA_DB` | `<home>/lovia.db` |
| `--app MODULE:ATTR` | `LOVIA_APP` | 创建默认 Agent（或使用自己的 Agent、映射或应用） |
| `--title` | `LOVIA_TITLE` | `lovia` |
| `--log-level` | `LOVIA_LOG_LEVEL` | `info` |
| `--check` | — | 检查模型配置并退出 |

绑定地址只决定要不要令牌：监听 `0.0.0.0` 的服务（比如在容器里）和监听 `127.0.0.1` 的一样，
所有模式、目录和远程工作区都可用；部署方用上面三个参数收紧。0.9.179 之前，监听非本机地址时
模式最高只到 `coding`、对话只能在 `DIR` 里，除非加 `--allow-workspace-switch`；这个参数已删除。

0.9.146 起移到设置页的选项（`--trusted`、`--auto-allow`、`--max-turns`、`--max-retries`、
`--max-tokens`、`--no-followups`、`--no-memory`、`--no-subagents`、
`--instructions`、`--instructions-file` 及对应的 `LOVIA_*` 环境变量）会让 CLI 报错退出，并说明
改到了哪个设置；`--memory-dir` 会指向 `--home`。自定义的 `--app` Agent 使用 CLI 默认值，要调整上限请在代码里用
`create_app(max_turns=…, retry=…, followups=…)`。完整列表以 `lovia web --help` 为准。

## 审批

[权限](tools.md#工具审批)判定为 `ask` 的 Tool 会让运行停在一张卡片上：卡片用 Tool 自己的名称
发问（“允许运行命令吗？”），有值得一提的*理由*时在下面补一行（“Pushes commits to a remote.”），
再原样显示模型发出的调用，然后是**允许**和**拒绝**——拒绝时可以附几行原因，模型会看到它并换做法，
而不是重试（⌘/Ctrl+Enter 直接带着原因拒绝）。卡片出现时会拿到键盘焦点，但焦点不在“允许”按钮上：
误按 Enter 不会批准任何东西。

判定给出了*范围*（`shell:git push`、`read:~/notes`）时，卡片还会提供**本对话中总是允许**，
放开的正是这些范围——像 `echo a; uname -a | head -1` 这样串起来的命令会列出要记住的每个命令
（`echo` `uname` `head`）；其中有一部分无法授权（`sudo`、shell 会展开的 `$VAR`）时就一个也不提供。
勾选框一次选中全部，点某个命令可单独取消（还没勾选时点它，就只选它这一个）——于是可以记住 `pwd`、
`uname` 而不带上 `python`。本次调用仍然整条运行，挑选只决定以后哪些调用不再询问。授权存在服务端，按对话记录，并绑定到给出时的 agent 和工作区根目录：之后被完全覆盖
的调用在任何人看到之前就已批准，不出卡片；对话换到别的工作区时不会沿用。授权永远不作用于
`deny`，新对话和子 Agent 任务也不会继承。

卡片只在等待决定时出现。一旦有了结论——你、另一个标签页、超时还是停止——卡片消失，结果以标签的形式
留在这次调用自己的工具行上：**已允许**（悬停可见记住了哪些）、**已拒绝**（悬停可见拒绝原因）、
**超时拒绝**、**已停止**；被授权自动放行的调用标为**自动允许**，点它可以查看这个对话的授权并撤销
（撤销只影响之后的调用）。被拒绝的调用当场补上工具行，随后由它的报错结果填充，和刷新后看到的一致。
`lovia web` 对 10 分钟无人回答的审批自动拒绝（卡片上事先写明时刻；模型会被告知用户没有回应），
这样定时任务和后台任务不会长期占用运行槽位；自己的应用用 `create_app(approval_timeout=...)` 设置
（`None` 表示一直等待回答）。

## 来自 Agent 的提问

默认 Agent 带有 [`ask_human`](built-in-tools.md#询问人工) Tool。等待中的问题保存在服务端，
所以刷新或重新连接不会丢失。默认 10 分钟无人回答时，调用会取消，模型收到 Tool 错误后继续；
这也避免定时任务和后台任务长期占用运行槽位。

自定义 Agent 需要把同一个 `HumanChannel` 同时交给 Tool 和 Web 应用：

```python
from lovia import Agent
from lovia.tools import HumanChannel, ask_human
from lovia.web import create_app, serve

channel = HumanChannel()
agent = Agent(name="bot", model="<model>", tools=[ask_human(channel)])
serve(create_app(agent, question_channel=channel, question_timeout=600))
```

## 追问建议

追问建议来自一次独立模型调用，不会写入 Transcript。关闭它可以避免这次额外调用：在**设置 →
Agent** 里给某个 Agent 关闭，也可以把辅助任务角色指派给更便宜的模型（见[模型配置与切换](#模型配置与切换)）。
通过 `create_app()` 托管自定义 Agent 时，该功能默认关闭，需要显式开启，见
[Web 服务端](web-server.md#追问建议)。

## 运行与连接的边界

Run 由服务端托管，刷新或关闭页面不会取消它；重新连接后会从服务端状态继续。显式停止 Run 时，
已经完成的 Turn 仍保留在 Session 中。

服务优雅关闭时会保留主 Run 的 Checkpoint，重启后可以恢复；审批和 SSE 订阅等进程内状态不会恢复。
Shell 后台进程和后台子 Agent 也不会随 Checkpoint 恢复。

Run 执行期间发送的消息有两种处理方式，按条决定：

- **排队**（Enter）：消息显示在输入框上方，等当前 Run **成功完成**后作为单独的 Run 发送。多条排队消息逐条发送，
  每条都等上一条的 Run 完成。Run 失败或被停止时队列会暂停，可以点「立即发送」或撤回消息继续。
  排队消息只保存在当前浏览器标签页中：仅在该对话打开时发送，刷新页面后会丢失。
- **插话**（⌥/Alt+Enter，或排队消息上的「插话」）：作为当前 Run 下一 Turn 的追加指令；如果当前 Run
  恰好结束，用 ⌥/Alt+Enter 发出的会按顺序进入新的 Run，从队列插话的则回到队首，照常排队。
  插话没有收到应答（例如网络中断）时，它可能已经送达，所以不会自动重发：它停在队首并暂停，等你核对对话。

Run 执行期间也可以添加附件，它们随消息一起发送，无论排队还是插话。有附件还在上传时，「发送」会等上传完成。
排队消息还可以放回输入框编辑（输入框和附件栏都为空时，文字和附件一起放回），或者撤回。

## 分支对话

每条已完成的回复上都有 **在新对话中分支**：它新建一个对话，包含到这条回复为止的全部内容，
你可以从这里把对话引向另一个方向。从最后一条回复分支，就是复制整个对话。某条回复之后若有
仍在运行的 Run，这条回复要等该 Run 结束后才会出现分支按钮。分支复制的是服务端当时保存的
内容。原对话不受影响，新对话会链接回原对话，删除其中一个不影响另一个。

分支复制的是对话，不是工作区：分支点之后写入的文件保持当前状态。

让 agent “在新对话里”做某件事时，它可以自己新建对话（`start_session`）。点击工具卡片即可打开
新对话；新对话不带当前对话的任何内容，并会链接回发起它的对话。

## 后台子 Agent

`lovia web` 默认启用[后台子 Agent](multi-agent.md#后台子-agent)，可在**设置 → Agent** 里给某个 Agent 关闭。
默认子 Agent 保留 Skills、Todo、Tool 和 Workspace，但不加载 Scheduling、Memory 或 Subagents，
因此不会递归派生。

自定义 Agent 需要自行添加 `Subagents` Plugin。`create_app()` 会把使用默认执行方式的 Plugin
接入 Web 托管；可用 `create_app(..., wire_subagents=False)` 禁用。直接挂载
`build_api_router` 时，需要调用一次 `wire_subagents(deps)`。

每个后台任务都有独立 Session。任务完成后，报告会送回父对话：父 Run 仍在执行时进入下一 Turn；
父对话空闲时，服务端会自动启动一次 Run 处理报告。浏览器无需保持在线。

后台任务不属于父 Run，因此停止父 Run 不会停止它；删除父对话则会停止它的后台任务，并一并删除。等待审批超过 `approval_timeout` 时会自动拒绝；
服务重启后，尚未完成的后台任务不会恢复。
