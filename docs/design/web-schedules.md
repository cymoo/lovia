# 定时任务：从弹窗到页面

> 状态：已定稿，实施中（第 1 个 PR：v0.9.200） · 2026-11-14 · 范围：`lovia/web`（`scheduler.py`、`scheduling.py`、`store.py`、`schemas.py`、`api/schedules.py`、`static/js/schedules.js`、`views.js`、`sessions.js`）。core 与 workspace 引擎不改。
>
> 行号指向 `main`（`afec54b7`，v0.9.199）。

## 结论

定时任务现在是一个 640px 宽的弹窗，列表、详情、表单三个状态轮流显示。这次改成主区域里的内置页面（`?view=lovia-schedules`）。页面分列表和详情两级，新建和编辑仍用对话框。

功能上补六件事，每件都对应一个现有缺口：

1. **名称**：任务有自己的名字，列表不再只显示截断的 prompt。
2. **预设频率**：选"一次 / 按天 / 间隔 / Cron"，不再手填秒数和 cron。保存前就能看到接下来三次的运行时间。
3. **运行位置**：页面上新建的任务可以选文件夹和权限模式。现在只有模型调用 `schedule_run` 能设置这两项。
4. **结果去向**：表单和详情里都显示"每次新开对话"还是"续写某个对话"。
5. **可追溯**：触发时新建的对话带上来源标记。侧栏和对话顶栏都能跳回对应任务。
6. **跳过也入历史**：上一次运行还没结束而跳过的触发，在历史里显示为"跳过"并写明原因。

不新增表，不加依赖。`chat_schedules` 只加一列 `name`。

## 1. 现状

现在的列表是弹窗里的一组行，每行显示状态点、截断的 prompt、等宽字体的元信息和一个开关。详情和表单在同一个弹窗里切换。

| 问题 | 原因 |
| --- | --- |
| 列表只能靠截断的 prompt 区分任务 | 没有名称字段（`store.py:457`） |
| 频率要先选类型，再手填原始表达式：间隔填秒数，cron 自己写 | `buildExprInput`（`schedules.js:111`） |
| 页面上新建的任务只能跑在 agent 的默认目录和默认权限下 | `ScheduleSpec` 没有工作区字段（`schemas.py:556`），只有 `schedule_run` 工具会写入（`scheduling.py:274`） |
| 看不出任务是续写某个对话，还是每次新开对话 | API 支持 `session_id`，UI 没有显示，也不能设置 |
| 每次触发新建的对话混在侧栏里，看不出来自哪个任务 | 触发时的 `upsert` 不写来源（`scheduler.py:300`） |
| "上一次运行还在进行"的跳过不留记录，只有 miss 会记成 failed | `scheduler.py:246`；miss 走 `scheduler.py:358` |
| 详情和表单共用一个小弹窗，看历史和改配置互相挤占；日期用等宽字体 | 弹窗是三个视图轮流显示的结构（`schedules.js:229`） |
| 无人值守运行遇到需要批准的工具，会等 10 分钟后自动拒绝，表单里没有任何提示 | `approval_timeout=600`（`__main__.py:715`），`supervisor.py:493` |
| cron 按服务器时区解释，但表单没有说明 | `_croniter_next`（`scheduler.py:57`） |

## 2. 其他产品怎么做

| 产品 | 入口 | 频率 | 运行位置 | 结果 | 历史 |
| --- | --- | --- | --- | --- | --- |
| Claude Code Desktop | 侧栏 **Scheduled** 页面，列表 → 详情 | Hourly / Daily / Weekdays / Weekly / Manual，Custom 用 cron | 文件夹、权限模式、模型、worktree | 每次运行新开一个会话；侧栏可开 Scheduled 分组 | 列出每次运行，含跳过；悬停显示原因（休眠、上次未结束、并发） |
| Claude Cowork | 侧栏 **Scheduled** → New task（"Create with Claude" 或手动） | hourly / daily / weekly / weekdays / manual | 文件夹、审批模式、模型 | 和普通任务一样查看 | 页面上看过去和将来的运行 |
| Codex / ChatGPT 桌面版 | 侧栏 **Scheduled**，兼作收件箱 | 分钟间隔、每天、每周，高级用 RRULE | 项目、本地或 worktree、模型；沙箱用默认设置 | 独立任务每次新开对话，对话内任务回到原对话；有未读标记 | 最近运行 |
| ChatGPT Tasks | **Scheduled** 页面 | 对话里描述，页面里编辑 | 无 | 每次一条结果，推送或邮件通知 | 打开任务看历次回复 |
| OpenClaw | Control UI 自动化页 | cron | 独立会话或主会话 | 投递到频道或 webhook，失败可另行路由 | 运行历史 |

几家共同的做法：

- 都有独立的 **Scheduled 页面**，没有一家用弹窗。
- 频率用**预设加时间选择器**，cron 只作为"自定义"的兜底。
- 每个任务都有**名称**。列表行显示名称、频率、下次运行和状态。
- 详情页的操作基本一样：**立即运行、启用/暂停开关、编辑、删除**。历史里也显示**跳过**的运行和原因。
- **运行位置**（文件夹、权限）是表单里的一等字段。
- 结果要么**每次新开对话**，要么**续写原对话**。

## 3. 设计

### 3.1 入口与 URL

侧栏的"定时任务"不再打开弹窗，改为打开内置视图 `lovia-schedules`。`views.js:89` 已经把 `lovia…` 前缀留给内置使用，所以不会和部署方注册的视图冲突。

- 列表：`?view=lovia-schedules`
- 详情：`?view=lovia-schedules/<id>`

浏览器后退可用，链接可以分享。视图盖在对话上方，下面的对话照常运行，语义和 `web-views.md` §3.2 一致。`views.js` 需要一个内部的 `registerBuiltinView`，跳过保留前缀检查；部署方的 `registerView` 不变。

### 3.2 列表页

```
定时任务                                                 [+ 新建任务]

已启用 · 3
 ●  每日 issue 汇总      工作日 09:00    下次 周一 09:00    ✓ 2 小时前   [⏻]
    ~/repo/lovia · 每次新开对话
 ◐  CI 检查              每 30 分钟      运行中…                         [⏻]
    直到「所有 job 都是绿色」 · 3/20 次
 ●  提醒准备设计评审      一次           今天 12:43                       [⏻]

已暂停 · 1
 ○  周报草稿             每周一 10:30                                   [⏻]

▸ 已结束 · 2                                         （默认折叠）
```

- **行内容**：名称（没有名称时取 prompt 首行）、频率的自然语言描述、下次运行（相对时间，悬停显示完整时间）、上次结果（✓/✕ 加相对时间）、启用开关。第二行用淡色显示运行位置、结果去向、停止条件和安全上限，只显示设置过的项。
- **运行中**：状态点换成转圈，"下次运行"换成"运行中"，点击直接打开正在运行的对话。
- **分组**：已启用 / 已暂停 / 已结束。"已结束"包括设置了 `finished_reason` 的任务和已经过期的一次性任务，默认折叠。
- **行尾 ⋯ 菜单**：立即运行、编辑、复制、删除。点击行进入详情。
- **空状态**：一句说明，加三个示例（"每个工作日 9 点汇总新 issue""每 30 分钟检查 CI，直到全部通过""明天 9 点提醒我…"），点击后带内容打开表单。再加一行提示："也可以直接在对话里说'每天 9 点…'"。

### 3.3 详情页

```
← 定时任务
每日 issue 汇总                         [▶ 立即运行]  [⏻ 已启用]  [⋯]
工作日 09:00 · 下次 周一 11-16 09:00

指令
  汇总昨天 GitHub 上 lovia 仓库的新 issue 和 PR，按优先级列出需要我处理的
  （超过 12 行时折叠，"展开"）

设置
  频率       工作日 09:00            （悬停：cron 0 9 * * 1-5 · 服务器时区 UTC+8）
  运行位置   ~/repo/lovia · 默认权限
  结果       每次新开对话             或：续写「CI 排查」↗
  Agent      lovia                    （仅多 agent 时显示）
  停止条件   所有 job 都是绿色
  安全上限   已触发 3/20 次 · 11-20 到期

运行历史
  ✓ 11-14 09:00   成功    1 分 12 秒 · 12,345 tok      打开对话 ↗
  ⤼ 11-13 09:00   跳过    上一次运行仍在进行
  ✕ 11-12 09:00   失败    agent 'x' 不再提供
  ◐ 11-11 09:00   运行中                                打开对话 ↗
                          [加载更多]
```

- 主要操作放在标题右侧：立即运行、启用开关、⋯（编辑 / 复制 / 删除）。删除需要二次确认。
- 已结束的任务把开关换成"重新启用"。如果停在 `max_fires`，同时提示"先在编辑里调高次数"，因为现在只恢复启用的话会在下一次触发后立刻再停（`fire_count` 不会回退）。
- 历史按时间倒序，每次加载 20 条。失败和跳过的原因直接显示在行内，不用悬停才能看到。
- 页面内容宽度和设置页一致（约 760px），单栏。

### 3.4 新建 / 编辑对话框

```
新建定时任务
  名称     [每日 issue 汇总                      ]   可留空，自动从指令生成
  指令     [                                      ]
           [                                      ]   （8 行，可拉高）

  频率     ┃ 一次 ┃ 按天 ┃ 间隔 ┃ Cron ┃                标签条
           按天：[一][二][三][四][五][六][日]   每天 · 工作日
                 时间 [09:00]
           → 接下来：周一 11-16 09:00 · 周二 11-17 09:00 · 周三 11-18 09:00

  运行位置 [📁 ~/repo/lovia ▾]  [权限：默认 ▾]           复用输入框的文件夹和模式选择器
  结果     (•) 每次新开对话
           ( ) 续写「CI 排查」                            只在任务绑定了对话时出现

  ▸ 高级：停止条件 · 最多次数 · 到期时间 · Agent

  ⓘ 运行时无人值守：需要批准的操作会等待 10 分钟后被拒绝。
    要写文件或执行命令，请选"完全访问"，或把相关工具设为始终允许。

                                                  [取消]  [创建]
```

**频率**用四个标签，各自对应一个 `trigger_kind`，不需要改后端：

| 标签 | 控件 | 存储 |
| --- | --- | --- |
| 一次 | 日期时间，带快捷项"1 小时后 / 明天 9:00" | `at`，epoch |
| 按天 | 星期多选（快捷：每天 / 工作日）+ 时间 | `cron`，`M H * * DOW` |
| 间隔 | 每 N 分钟 / 小时 / 天 | `every`，秒数 |
| Cron | 原始表达式，下方显示自然语言描述 | `cron` |

编辑已有任务时：如果 cron 能用"按天"表示，就打开"按天"标签，否则打开"Cron"。选项只有四个，所以用和文件面板一样的标签条，不用原生下拉框。

"接下来"一行由新增的 preview 接口给出（§3.5）。它显示的是浏览器本地时间。如果服务器时区和浏览器时区不同，在后面加一句"（按服务器时区 UTC+0 计算）"。

**高级**默认折叠：停止条件、最多次数、到期时间，多 agent 时还有 Agent 选择。编辑时只要其中有已设置的值，就自动展开。

**新建时的默认值**：文件夹和模式取当前对话的设置，和新对话的默认值一致。从对话的 ⋯ 菜单"为这个对话创建定时任务"进入时，"续写此对话"默认选中（ChatGPT 的线程内任务就是这样）。这个入口放在 §4 第 3 个 PR。

### 3.5 后端改动

| 改动 | 位置 | 说明 |
| --- | --- | --- |
| `name` 列 | `store.py` 迁移（和已有的 `ALTER TABLE` 一样）、`ScheduleSpec` / `Patch` / `Info` | 可空。前端在空值时用 `provisional_title(input)` 显示。`schedule_run` 工具加可选参数 `name` |
| 工作区字段上 API | `ScheduleSpec` / `Patch` / `Info` 加 `workspace_root`、`workspace_mode` | 创建和修改时走 `deps.admit` 校验，和新建对话同一个关卡。省略时行为不变（用 agent 自己的目录） |
| 触发对话的来源标记 | 触发时新建对话写 `origin_kind="schedule"`、`origin_ref=<schedule id>` | 复用分支和 spawn 已有的来源列，不加新列 |
| 跳过记录 | `scheduler.py:246` 上次未结束而跳过时，写一条 `status="skipped"` 的运行记录，`error` 写原因 | 每个时间槽都会 `_advance`，所以每槽最多一条。到达并发上限的延后（`scheduler.py:329`）每秒重试，不记录 |
| preview 接口 | `POST /api/schedules/preview` `{trigger_kind, trigger_expr}` → `{next_fires: [3 个 epoch], tz_offset}`；无效时返回 422 | 复用 `validate_trigger` 和 `advance_next_fire`，约 20 行。表单输入时节流调用（300ms），cron 写错能在保存前看到 |

`run_record` 的 `status` 本来就是普通字符串（`store.py:558`）。前端遇到 `skipped` 时不弹运行通知，侧栏状态也不受影响，因为这条记录没有 `session_id`。

### 3.6 对话那一侧

- **侧栏**：`origin_kind="schedule"` 的对话行前加一个时钟小图标，悬停显示任务名称。
- **顶栏**：复用 `origin-btn`（分支已经在用的那个按钮），显示"来自定时任务「每日 issue 汇总」"，点击打开任务详情。
- **续写型任务**：被续写的对话在顶栏显示"⏰ 1 个定时任务"，点击打开详情（ChatGPT 的做法）。实现方式是前端用 `session_id` 在任务列表里查，不需要后端改动。

## 5. 明确不做

| 不做 | 理由 |
| --- | --- |
| 收件箱和未读分拣（Codex） | lovia 已有运行通知（toast、系统通知、标签页标题计数）和侧栏。再做一个收件箱就是第二套未读状态 |
| "手动"频率（Claude） | "暂停 + 立即运行"已经能做到同样的事 |
| 每个任务单独选模型 | 模型属于 agent 和配置角色。需要不同模型时，建一个自定义 agent 再选它 |
| worktree 隔离 | 工作区层没有 worktree 的概念 |
| 列表搜索和过滤 | 任务通常不到 20 个，分组已经够用 |
| 错过的触发补跑 | 现在逾期只触发一次（合并），和 Claude Desktop 一致 |
| 事件触发（webhook、GitHub） | 这不是定时任务，是另一个功能 |
| 一个任务一天多个时间点 | 用多个任务或 Cron 标签就能做到；"按天"标签只支持一个时间，保持简单 |

## 6. 已定

2026-11-14 按建议定稿：

1. **做成页面**（§3.1），`views.js` 加内置注册入口。
2. **新增 `skipped` 状态**（§3.5）。`latest_run_for` 不把它算作最近结果，运行通知也不显示它。
3. **cron 继续按服务器时区执行**，表单在时区不同时提示。没有给任务存时区。
4. **侧栏只加时钟图标**（§3.6），不单独分组。

实施时的一处细化：通过 HTTP 创建的任务只在请求里带了 `workspace_root` 时才存目录，不带时存 `None`，这样任务跟随 agent 自己的目录；权限模式和新建对话一样，省略时取服务器的 `default_mode`。
